# 阶段清单 · 场景计划（scene）

> 由 `docs/whiteboard_registry.py render` 从 `docs/whiteboard/lessons-learned.yaml` 生成，**不要手改**；要改规则，改登记表再重新运行并提交。

**口令**：场景计划通过

**本阶段做什么**：
1. 复制 `build_scene_plan.py`，改各块版面与事件；每个事件带 `anchor_phrase`，事件按旁白先后顺序写，找不到锚点就停下改计划，不放宽查找。
2. 改静默表与 `MIN_AFTER`（按本课问答所在段）。
3. 运行（会把 script 检查点标为 completed），写 scene_plan 检查点 awaiting_human，停下等“场景计划通过”；用户说了之后：`docs/whiteboard_gate.py approve <项目> scene_plan "<用户原话>"`。

**产出**：scene_plan.json；scene-plan-review.html

**已由脚本拦下**（先跑，红了就改，不要放宽阈值）：
- **[E76]** 新系列的场景计划：每个场景的 movement 以“呈现手段：手段一、手段二；…”开头，手段取自 docs/whiteboard/series.yaml 的 devices（便条飞行、聊天气泡、柱状图、插画卡片、圈注与荧光笔、镜头推近、角色表演、色块与分区、代码与结果面板、纯板书）；按教学内容选最合适的手段（概念比喻→插画与角色、流程传递→便条飞行、数据对比→柱状图、真实界面→气泡、定义→便利贴、预测题→彩色题卡）；整课只有纯板书、或总共不足 4 种手段，检查会警告。运行：.venv/bin/python docs/whiteboard_scene_plan_check.py projects/<课程>。 —— 试验课整篇只画方框，用户评价“表达手段过于单一”，并要求彩色插画、会动的图解、真实界面与图表、色彩与版面语汇四类手段都具备、按内容选 〔脚本：`docs/whiteboard_scene_plan_check.py`〕
- **[E98]** 分镜里的 movement 和 description 不写“出现、显示、展示、淡入、逐条”（“出现次数”“出现过”这类不算）：它们说的是结果，不是动作。写成画面里那个物自己的动作（飘进来、写出来、被圈住、翻过去、跳出来）；写不出动作的场景先别做。检查只提醒（WARN）。 —— 借自开源技能 huashu-art-motion（MIT）的分镜规则，2026-11-01 评估。第 1 课实测：17 个场景里 3 处（sc08、sc11、sc13）用了这些词，其余已经是具体动作，缺口小，所以只做提醒 〔脚本：`docs/whiteboard_scene_plan_check.py`〕

**要人判断**（逐条过一遍）：
- **[E34]** 每个画面事件带旁白锚点，事件按旁白先后顺序写，后续锚点必须在主锚点之后；锚点被前一个锚点消耗后用 A(S, …) 单独重找；逐张演示先打印各锚点的实际时间，按它们逐步定时，不要按整段平均分配。 〔第 25、28 课〕
- **[E35]** build_scene_plan.py 的静默表与 MIN_AFTER 按本课问答所在段改（问答在哪几段就是哪几段，不总是 s3 与 s8）；样音也不一定在 s2。 〔第 41、43 课；拟做成脚本：从 script.json 的 quiz_pauses 自动生成（可选）〕
- **[E36]** 只出现一段时间的画面（结果行、中间态、问号、框）都要写擦除时间 until，指向它的箭头也设同样的 until；框和单元格自己带 until，不要拿底色矩形去盖；“先填问号再写字母”的小格用 until 去掉问号。 〔第 32、34 课〕
- **[E92]** 角色按需出场：旁白讲到它或它有动作才在场，其余时间只留老师；进场从老师身边走出来，离场向老师那边退着淡出；站位按时间量出板上的空位再定（docs 里没有现成工具，本课的小工具在项目 scripts/board_free_space.py）；数步子的段落板上往往没有空地，用原地蹦，不要承诺沿着步数条走。场景计划里写出每个角色的在场区间和依据。 —— 搭档原来 99% 的时间（428.8 秒）站在老师旁边，约 74% 只是站着挥手、听、思考，旁白只有约 22% 的句子讲它；用户说像摆设。改后约 49%（209.8 秒、9 段），调度表在项目 assets/image_specs/ROBOT_CHOREO.md
- **[E128]** 画真表的数字、模型名、日期、种数一律由代码从数据文件现读（real_tables.json、从 validation/real_runs 正式记录现算的 rows_data.json），板书里手写的数字为 0，并在共用件里断言；有逐次原始记录就按真实顺序和重复情况着色，不画“示意排列”（种数与已有数字逐一核对相等）。共用件（装配图卡、真表柱、章、脚注、气泡、旋钮）在派板书之前由我写好冻结，板书文件只调用不改。 —— 第 3 课四块板、1112 个板上元素，实测数字 0 处手打、模型名日期 0 处手打；十格行本来按计划画“示意排列”，有了正式记录后改成真实的顺序和重复。
