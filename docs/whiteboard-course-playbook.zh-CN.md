## 0. 一页摘要

**十五条最重要的原则**

1. **一课只解决一个“认知冲突”。** 冒泡排序：为什么反复比较相邻两数就能排好；传参：为什么 `swap` 函数交换不了。
2. **用故事导入，并做一张“故事 ↔ 代码”的一一映射表。** 映射不出来的故事，不要用。
3. **先直觉，后代码。** 每一行代码都要能指回一个已经演示过的动作。
4. **先演示“失败版”，再演示“成功版”。** 对比比单讲成功版记得牢（值传递失败 → 地址传递成功）。
5. **数字和输出都必须真实。** 手算过的例子、`gcc` 真实运行的输出；没实测的数值不要编。
6. **一段旁白配一块白板。** 一屏文字要少，状态要一步一步出现，旁白说到哪、笔写到哪。
7. **数字、代码、公式、内存图用代码绘制；AI 插图只做比喻配图。** 角色用“定妆图 + 垫图”保持一致。
8. **术语先定、全片一致。** 用户更正过的术语（本课只讲两种传参）要写进术语表，脚本、板书、字幕、简介全部遵守。
9. **先出样片再批量，每个门单独批准。** 最难的一段先做配音样片；内存图先渲染静态帧再渲染整片。
10. **交付前独立核对，不信工具自检。** `ffprobe`、响度、黑帧、抽帧目测；做不到的检查要明说并给出替代证据。
11. **系列课沿用同一角色、术语和隐喻。** 写完脚本先对照上一课审查：术语有没有冲突、角色有没有换名、上一课的哪句话要回扣（第 3 课的 v1 就栽在这里，见 2.11）。
12. **场景计划里每个画面事件都带旁白锚点。** 只写估计秒数会让动作比旁白早 3–6 秒；剪辑阶段用锚点短语定位，找不到就回头改计划。
13. **旁白里点名的每个字符、数字、元素，开画前和画面逐一对照。** 第 4 课旁白说“后面的 p、l、e 还在”，实际 apple 的下标二换成终点牌后只剩 l、e；这是画画面时才发现的，只能重生成一段配音。对照表要在脚本阶段做，不要等到剪辑。
14. **选题先研究再定，四条标准都过才建项目。** 前置讲过没有、能不能从最近一两课自然长出来、新东西是不是只有一两个、核心结论能不能实测；用户随口提的题目只是想法，可以否定（第 11 课：选择排序接不上指针线，链表缺申请内存与空指针，先做动态内存分配，见 2.16）。
15. **每课都要回答“难点怎么讲、怎么算学会、讲得够不够通俗”。** 难点表（难点→学生怎么想→讲法→实测证据）、通俗度自查（平均句长 ≤24 字、最长 ≤50 字、旁白无英文字母与数字，写成脚本里的断言）、课后练习（第 11 课起随发布包分发，答案全部实测）。

**开新课 10 步（速览）**

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 问清受众、前置知识、时长、想用的隐喻 | 需求卡 |
| 2 | 定“认知冲突”与术语表 | 一句话教学目标 |
| 3 | 设计隐喻映射表与边界说明 | 映射表 |
| 4 | 选例子并手算/实测（`gcc` 运行） | 例子与真实输出 |
| 5 | 写 10 段左右脚本（每段 ≤600 字） | `script.json`（门） |
| 6 | 写场景计划：一段一板、图示语言、插图清单、**每个事件的旁白锚点** | `scene_plan.json`（门） |
| 7 | 素材：配音样片 → 定妆图 → 批量配音与插图 | `asset_manifest.json`（门） |
| 8 | 剪辑：锚定时间、抽帧看版面、30 秒样片 | 样片（用户审） |
| 9 | 合成整片并独立核对 | `final.mp4` 与验收记录 |
| 10 | 发布包（缩略图、字幕、章节、简介）→ 用户批准 | `exports/`（门） |

## 2. 重点：如何设计一门成功的白板课程

### 2.1 选题：一课只解决一个“认知冲突”

好的白板课不是“把知识点讲一遍”，而是让学生带着一个疑问进来，带着一个“原来如此”出去。

| 课 | 学生进来时的疑问 | 一句话教学目标 |
|---|---|---|
| 冒泡排序 | 只准比较相邻两个数，怎么能排好整个数组？ | 反复比较相邻两数、大的往右换，每一轮把当前最大的数浮到最右边 |
| 函数传参 | 我写了 `swap` 函数，为什么两个数纹丝不动？ | 值传递改的是副本；把地址交给函数，才能改到原变量 |

**做法**

- 先写出这句“教学目标”，全片只服务它。超出目标的内容（比如传参课里的数组作参数、`const`）放进“后续课路线图”，不塞进本课。
- **写清前置知识和“还没学”的边界。** 传参课假定学生没学指针，所以：`int *px` 只解释成“这个变量里装的是一个地址”，不展开指针运算；指针单元格里写“a 的地址”，不写十六进制。
- 时长按内容定，不按习惯定。传参课原本想 5–8 分钟，实际按“故事 + 门牌号铺垫 + 两版完整演示 + 进阶”估算，成片近 8 分钟。

### 2.2 故事/隐喻导入

**好隐喻的五条标准**

1. **能一一映射**：故事里的每个角色和动作，都对应代码里的一个东西。
2. **有反差**：让学生先“猜错”。克隆门里手术做了，本人却毫发无损。
3. **可画**：能画成简单线稿，笔画不复杂。
4. **可回扣**：结尾能回到同一个故事收束（“你派去手术的，只是克隆体”）。
5. **边界说得清**：明确告诉学生隐喻在哪里失效。

**克隆门案例拆解**

| 故事 | 代码 |
|---|---|
| 本人 | `main` 里的变量 |
| 克隆门 | 函数调用 |
| 克隆体 | 形参（实参的副本） |
| 手术 | 函数里的修改 |
| 手术后克隆体消失 | 函数返回，形参被释放 |
| 医生拿到家庭地址 | 传给函数的地址 |
| 上门手术 | 顺着地址（`*px = …`）修改原变量 |
| 地址纸条是抄来的 | 指针形参本身也是地址的一份拷贝：函数里改 `p` 的指向，外面的指针不变 |

**结构**：故事一（克隆门）→ 故事二（上门手术）→ **揭晓**：把上面的表逐行写在白板上 → 后面所有演示都用故事里的词（“过克隆门”“上门手术”）。

**隐喻的边界（一定要说出来）**：“克隆门只是比喻，比喻的是数据被复制，别把比喻当成真的有人在被传送。”放在进阶段落，防止过度类比。

**反例**

- 隐喻没有收尾：开场讲了故事，后面再不提。→ 结尾必须回扣。
- 把比喻当机制：学生以为“地址传递就是什么都没复制”。→ 用“地址纸条是抄来的”纠正。
- 中文语境的注意：用户原话是“中国人去韩国整容”，脚本里主角用中性名字“小明”，不做国籍刻板化描写，并在提案阶段请用户确认。

### 2.3 课程骨架模板

传参课的 10 段结构可以直接当模板。冒泡排序的 14 段是同一思路（比喻 → 规则 → 逐轮演示 → 规律 → 代码逐行 → 验证 → 复杂度 → 优化 → 总结）。

| # | 段落 | 目标 | 传参课时长 | 字数 |
|---|---|---|---|---|
| 1 | 故事一 | 建立设定、制造反差 | 45 秒 | 208 |
| 2 | 故事二 | 给出第二种情形 | 26 秒 | 124 |
| 3 | 揭晓与映射 | 故事 ↔ 代码对照表 | 43 秒 | 194 |
| 4 | 前置概念 | 变量的“门牌号”、取地址符、真实地址 | 40 秒 | 215 |
| 5 | 失败版演示 | 值传递：代码 + 内存图 + 真实输出 | 83 秒 | 394 |
| 6 | 成功版演示 | 地址传递：代码 + 内存图 + 真实输出 | 86 秒 | 431 |
| 7 | 进阶/边界 | 地址纸条是抄来的；隐喻边界 | 44 秒 | 233 |
| 8 | 对照与选择 | 何时用哪种；回扣 `scanf` 的 `&` | 39 秒 | 226 |
| 9 | 常见错误 | 错/对成对呈现 | 30 秒 | 130 |
| 10 | 总结回扣 | 三句话总结 + 回到开场故事 | 33 秒 | 160 |

**节奏规律（三门课共同的）**

- 每段 30–90 秒；**演示段最长**（80–90 秒），导入和总结最短。
- 单段旁白 ≤600 字（配音接口限制），实际每段 130–430 字。
- 一段只推进一个动作：一个新概念、一个新符号、或一次演示。
- 全片 5–8 分钟对初学者是合适的；超过 10 分钟先删“常见错误”这类可选段。
- **一段一个动作，要拆就拆。** 第 3 课 v1 的 s5 有 449 字，同时讲地址副本、原数组被改、返回结果、函数头 `a[]` 等价 `*a` 四件事；拆成 s5（地址传递，约 280 字）和 s6（函数头，约 100 字）后，每段都能在板上完成一个完整的状态变化。经验：单段超过 350 字或要讲两个以上“新东西”，就拆。

### 2.4 例子设计

- **选“能看见算法在干什么”的数据。** 冒泡排序首版用 `[5,3,8,1,9]`，最大数 9 本来就在最右边，看不出“冒泡”；改成 `[7,3,9,1,5]`：9 从中间一路浮到最右，共 4 轮、10 次比较、6 次交换，第一轮既有交换也有“不用换”。
- **选定例子后先手算**，再让白板动画和旁白照它走。首版脚本写过“100 个数约 10000 次比较”，正确是 n(n−1)/2，即 4950 次。
- **数字同源**：脚本、白板、字幕、简介里的数字必须来自同一个地方，改一处要全改。
- **输出必须真实运行。** 传参课用 `gcc` 编译运行四个小程序（值传递失败版、地址传递版、指针形参拷贝版、打印地址版），所有输出与地址尾号（`f504`、`f4ec`）都取自实测。
- **不编造没测的值。** 没实测 `b`、`y` 的地址，就不在板上画它们的十六进制，指针单元格写“b 的地址”。板上的地址是某一次运行的结果，旁白要说明“每次运行不一样”。

**可运行例子的写法（第 5 课补充）**

- **编译用 `-Wall -Wextra -Wpedantic -Werror`，演示“改不到”的函数也要用到参数**：`fill_value(int x){ x = 42; }` 会因 `unused-but-set-parameter` 编译失败；在函数里加一句 `printf("inside fill_value: x=%d\n", x);`，既过编译，又给出“函数里确实是 42，回到主函数仍是 0”的真实输出。
- **输入类函数用管道代替键盘**：`printf '42 tea apple hi\n' | ./demo`，输出可复现；片中必须明说“用预先给好的输入代替键盘”。
- **故意写错的例子分两种**：能编译但行为未定义的（漏 `&`）只编译、保存 gcc 警告原文、**不运行**；会写出数组外的只在板上画叉。两种都不显示运行输出。
- **旁白点名的字符与输入顺序要对上**：读入 `hi` 覆盖 `apple` 后，终点牌后面剩 l、e；预测题答案、画面格子、字幕三处同源。

### 2.5 讲解设计

1. **先直觉，后代码。** 冒泡排序先讲排队，传参课先讲故事，最后才出现代码。
2. **代码逐行对应已演示的动作。** 冒泡排序的外层循环 = 轮数，内层边界 `n-1-i` = 已就位的不用再比，`temp` 是因为交换需要暂存。
3. **口语化读符号**（配音不读括号和下标）：

   | 写法 | 旁白读法 |
   |---|---|
   | `&a` | “and 符号 a”（讲解时说“取地址符”） |
   | `*px` | “星号 px” |
   | `int a = 3` | “int a 等于 3” |
   | `%p` | “百分号 p” |
   | `n-1-i` | “n 减 1 减 i” |
   | `arr[j] > arr[j+1]` | “数组的第 j 个元素是否大于第 j 加 1 个元素” |

4. **一次只引入一个新符号**：先讲 `&`（门牌号），再讲 `*`（到这个地址去）。
5. **进阶点放在主线之后**，并明确标为“还有一个细节”。
6. **错/对成对**：常见错误页左边写错误写法配红叉、右边写正确写法配绿勾，再用一句话收束（“`px` 是门牌号，`*px` 才是住在里面的人”）。
7. **总结三句话 + 回扣故事**，最后留一句有笑意的收尾。
8. **对照与选择**：明确告诉学生“什么时候用哪一种”，并回到他们每天写的代码（`scanf` 为什么要 `&`，`printf` 为什么不用）。

**预测题（先预测，再验证）——第 3 课的做法**

- 每道题**明确重置**到同一个初始数组（7 3 9 1 5），同一道题内连续调用不重置；两道题分别考“值传递 + 地址传递叠加”和“清零 + 值传递”，答案都来自 `gcc` 实测。
- 问句之后真的安静 3 秒：配音在两个问句处**切开成三段**，拼接时插入 3 秒真实静音；`narration_timeline.json` 记录每道题的 `question_end` 和 `answer_not_before`，答案、解题动画和答案字幕都不得早于它。
- 画面上用**三点倒数**（每秒亮一个小圆点）让停顿看起来是有意的；答案出来后一句话点明“第一次是值传递，只改了副本；第二次是地址传递，改了原元素”。

### 2.6 白板画面设计

**版面规则（1920×1080）**

| 区域 | 用途 |
|---|---|
| 左上角约 (40,38) 起 | 学校/机构 logo（深蓝底板），标题避开 x<330 |
| 左半屏 | 代码（等宽字体，字号约 33，行距约 50） |
| 右半屏 | 内存图、数组、输出面板 |
| y>900 | 字幕区，板书不要进入 |
| 白板内边距 28 | 不要贴边 |

**一段一板**：每个脚本段用一块新白板，段间用 0.4 秒淡出淡入“擦板”。同一块板内内容不清空，动作累加。

**颜色语义（全片固定）**

| 颜色 | 含义 |
|---|---|
| 黑 | 常规书写 |
| 红 | 动作、强调、错误（红叉、上门手术） |
| 绿 | 完成、正确（勾、本人毫发无损、就位） |
| 黄色荧光笔 | 当前正在讲的代码行 |
| 灰 | 已消失/已释放（形参变灰） |

**节奏**

- 笔尖指针跟着书写位置走；文字逐字“写出”，线条逐笔“描出”。
- 每个内存状态之间留约 0.5 秒，让学生看清；旁白说到哪，板上就出现到哪。
- 一屏文字量上限：一块板上主体不超过“一张表 + 一个图”或“一段代码 + 一个图”。

**内存图语言（`memory` 元素）**

| 画面 | 含义 |
|---|---|
| 方框，上方名字、下方地址 | 一个变量 |
| 值从源方框飞入新方框 | 复制（过克隆门） |
| 值闪黄并变红 | 被改写（手术） |
| 方框整体变灰后淡出 | 函数返回，形参消失 |
| 红色箭头 | 地址指向（医生拿着地址找到本人） |
| 灰色小字实测输出 | 真实运行结果 |

**冒泡排序的图示语言**：数组方块；比较用红圈；交换用弧线；已就位涂绿；每一轮在下面新开一行，右侧写计数和规则。

**字体**：手写体（ZCOOL 快乐体）中文好看，但**大写 O、C 是方形字形**（“大 O”看成“大口”），代码/公式里的大写字母用等宽字体，字幕里给该字符单独指定拉丁字体；**等宽字体没有中文字形**，含中文的输出行必须用手写体。

**数字 0 也是方块**：手写体里的 `0` 和全角 `０` 都是一个小四边形，像缺字。第 3 课实测对比了 `0`、`０`、`〇`、`o`、`Ø`、`零`，当时只有 **`〇`（U+3007）** 是清晰的圆，所以第 3 课板上的零写 `〇`。**第 4 课更正**：板上同时有 a p p l e 这类字母时，`〇` 像字母 o（用户指出）。字符格里和文字里的零改用**等宽字体的数字 `0`（带点，一眼是零）**：格子里的值置空，再用 `write(font="mono")` 居中叠写；文字行里中文用手写体、零用等宽字体分两段写（第 4 课的 `zero()` 与 `mixed()`）。`〇` 只在板上没有字母、纯数字时才可接受。凡是新课里会出现 0 的地方，先渲染一帧确认。

**大写字母同样是方块**：手写体里单个大写字母（T、E、A、O、C 等）都是方形字形。格子里的大写字母（第 4 课的 `TEA`）做法：先把该格的值置空，再用等宽字体 `write` 叠写（`upper()`）；结束符 `'\0'` 同理（`endmark()`：空格子 + 等宽叠写，红色）。这些小函数在 `projects/c-strings-cn/scripts/_build_body.py`，新课直接复制。小写字母 a p l e t h i x 在手写体里正常（l 画成一根斜杠，是字体本身的样子）。

**字幕里的 c、o 也要处理**：旁白里出现 `scanf` 这类含 c 的英文词时，字幕用手写体，c、o 会显示成方块。`_build_head.py` 里把单个大写字母指定拉丁字体的正则，第 5 课扩成 `[A-Zco]`（带手写体回退，否则全角标点会变方块）。**渲染一张含该词的字幕帧并裁出字幕条目测**，不要只凭正则。板上这类词（scanf、printf、`%d`、`&`、`'\0'`）一律用等宽字体。

**手写体中文与等宽词混排一行**：先写中文，再在其右侧用 `write(font="mono")` 接写等宽词或数字（第 5 课的 `hand_mono()`，按 `est_w` 估宽度排位）；整行要消失时两段都给同一个 `until`，否则等宽那段会残留。

**一次性小标注要给 `until`**：第 4 课 s3 的“数字字符 '0'”标注忘了设 `until`，对照表出现后它还残留在板上，渲染关键帧才看到。凡是只在某一阶段出现的标注、小格、圈线，都写明消失时间。

### 2.7 音画同步

- **用字幕短语锚定白板动作**：`build_edit.py` 里 `Finder.at("短语")` 找到该短语在字幕里的时间，白板动作按这个时间出现。短语要按文本先后顺序查找；同一段里乱序使用时用独立的查找器。
- **场景计划里就写锚点**：第 3 课的计划 v1 只给每个事件一个估计秒数，对照旁白发现 b01 的动作比对应的话早 3–6 秒（旁白还没说“外面的数没变”，交换动画已经出现）。v2 给 63 个事件都补了 `anchor_phrase`（旁白里的一句话，按先后顺序），另有 24 个“后续锚点”，让相邻锚点的间隔不超过约 8 秒；剪辑阶段 `Finder.at(anchor)` 一次全部找到。**找不到锚点就停下改计划，不用估计时间硬凑。**
- **事件清单要按旁白先后顺序写**：`Finder.at()` 只往后找。第 5 课 s2 的“这就是值传递”写在“医生也一样”之前，脚本阶段断言找不到锚点，调整顺序后通过——这是该防的错，不是 bug，不要放宽查找。
- **开场和板间不留空板**：旁白一提到“上一课医生”，医生就先淡入，再画病房；`&data[0]` 卡等到旁白说出“取地址符加零号元素”才出现，不提前。
- **字幕时间是估计的**：本机没有语音识别，脚本 `make_captions.py` 按静音区间和字权重分配时间，误差约零点几秒；必须在交付时如实说明。
- **分页**：字幕在标点和自然词尾处断页，不要按 16 字硬切（会把“排序”拆开）。
- **TTS 约定**：单次 ≤600 字；不支持 SSML，停顿靠标点和段间约 0.7 秒静音；返回的 WAV 头时长字段是错的，要先用 `ffmpeg` 重封装再量时长；拼成一条总旁白轨，`loudnorm` 到约 -16 LUFS。
- **样片门**：先用最难的一段（冒泡的第一轮演示、传参的值传递演示）做配音样片，用户确认音色和语速后再批量。

### 2.8 AI 插图的用法

**分工**：数字、代码、公式、内存图全部用代码绘制；AI 插图只做“比喻性配图”（学生、气泡、克隆门、医生、床、楼房）。

**统一线稿提示词前缀（三门课通用）**

```
黑色细线手绘线稿，纯白色背景，简洁卡通风格，线条粗细一致，没有阴影，没有灰色填充，没有任何文字。
```

负面词：`阴影，灰色填充，彩色，渐变，背景，边框，文字，字母，数字，水印，照片，写实`。人物加一句“全身完整入画，双脚和鞋子完整可见，四周留出足够空白，不要切边”。

**角色一致：定妆图 + 垫图**

1. 先单独生成主角、配角的**定妆图**（正面全身像），目测通过后固定。
2. 之后每个场景把定妆图作为参考图，提示词写“图 1 中的小明”“图 2 中的医生”，并写清**人数**（“画面中只有这两个人”）。
3. 传参课的 6 张场景图都这样生成，小明的发型、T 恤和医生的帽子口罩白大褂前后一致。

**逐张目测清单**

- 人物是否全身完整（曾有学生的脚被画布截断）。
- 人数是否正确（手术台那张首版多出一个站着的小明，重做后才对）。
- 有没有出现乱码文字（医生手里的纸条上曾出现乱码字母，改成“只画三条横线表示地址，没有任何文字”后通过）。
- 动作语义是否准确（“走进门”这类动作容易变成“站在门里”）。
- 抠底后线条是否平滑：AI 输出是不透明白底，用亮度转 alpha 并裁边，放在浅色白板上。

**重试规则**：最多 3 轮，仍不满意就问用户，或改用更符号化的画法；失败图保留为 `_v1` 文件，不覆盖。

**姿态图（第 3 课）**：同一个角色需要两个姿态时（医生持纸、指向右上方），都用前课定妆图作参考、各生成一张；先审 I01 通过，再生成 I02；每张最多 3 轮，失败图保留为 `_v1`/`_v2`，仍不合格就问用户，不自动改用云端生图。抠底用前课的 `postprocess_images.py` 函数（只读导入），输出写在本课目录。

**补充：本地生图**：仓库另有 `qwen_local_image`（本地 Qwen-Image，免费、可 1–4 张参考图垫图，文生图约 45 秒、带参考图约 65–95 秒，占共享 GPU）。DashScope 仍是默认；构图难控或赶时间用 DashScope，想省钱/离线用本地。

**网上说法要用实测核对（第 6 课）**：调研时搜索摘要里有“结构体含数组成员时，按值传递也能改到数组（数组会退化成指针）”，写实验程序跑一遍，结果是 `v` 仍为 `7 3 9`，说法不成立。做法：把它记进 `research_brief` 的误区和 `decision_log`（标明来源只是搜索摘要、未打开原页）；课里用“有人说……实测不是这样”温和纠正，不点名来源；脚本只引用自己的实测；脚本元数据里写一条 `claim_check`。**例子本身就是调研**：先写会出“反直觉结果”的实验，再决定要不要把它做成这一课的看点。

### 2.9 术语与准确性

- **先定术语表，全片一致。** 传参课只讲“值传递”和“地址传递”两种，用户明确更正后，脚本、板书、字幕、简介、提案全部按此执行，并在决策记录里追加一条术语决策。
- **审批后发现文案缺词**：传参课 s7 原句缺了“指针 q”，且旁白说 `px`、板书写 `p`。做法：只改这一句，只重生成该段配音，重算时间线和字幕，交付时告诉用户。
- **准确性自查清单**
  - 所有数字：手算或实测，脚本、板书、字幕、简介同源。
  - 所有代码输出：真实运行结果，不是想当然。
  - 不暗示错误结论（例如不能让学生以为“函数里改指针形参会改外面的指针”）。
  - 隐喻边界已说明。
  - 未实测的数值不出现在板上。

**旁白无英文的取舍（第 6 课）**：结构体课里 `struct`、`card` 含 c，旁白全部改用中文（结构体、病历卡、箭头、取地址符），代码和符号只写在板上的等宽字体，于是字幕里没有 c、o 的字形风险，也不用担心 TTS 读英文。代价是旁白与板上代码的对应要靠画面：每次说“箭头”“取地址符”时，板上要同时圈出 `->`、`&`。

| 失误 | 本次实例 | 修法 |

| 单段讲太多 | v1 的 s5 一段 449 字讲四件事 | 拆段（见 2.3） |

| 一次性标注残留 | s3 的“数字字符 '0'”没设 `until`，对照表出现后仍在板上 | 每个阶段性标注都写消失时间；渲染关键帧检查（见 2.6） |

| 缩略图取在动画中途或淡出时 | 第 5 课取 26.5 秒时病房只画了四间半，27.5 秒时整块白板已淡出变虚 | 取“画完且没淡出”的帧，先看图；本课最后取 27.2 秒（见 8.6） |

### 2.11 系列课的一致性与脚本自查清单

做系列课时，每写完一稿就对照上一课查一遍。第 3 课 v1 自审“通过”，对照本手册重审后却查出三个严重问题，所以**自审要有清单，不能凭感觉**。

| 查什么 | 怎么查 | 第 3 课的实例 |
|---|---|---|
| 术语 | 把上一课的术语表当检查表，全文搜索冲突词 | “传值规则”与“只讲值传递 / 地址传递”冲突 |

### 2.12 讲抽象概念：指针初步（第 7 课）

- **选题**：把前六课反复用到、却一直没细说的“地址纸条”落到变量上（`int *p = &age;`），再回答最常见的疑问：声明里的星号和使用时的 `*p` 是不是一回事。
- **一个符号两个意思**：用“出现的位置 / 意思”对照表讲，口诀是“先看它出现在哪里”——声明里是说明（格子里装的是地址），使用时是顺着地址走一趟。表里代码用等宽字体，意思用手写体。
- **改纸条 vs 改病房**：并排演示 `*q = 9;`（顺着纸条，病房变）与 `p = &n;`（只换纸条上的字，原病房不变），再顺着新纸条写 3，只有新病房变。数值沿用上一板不清屏（s3→s4→s6 是连续的一次演示：age 依次 7、8、9），两题预测题之间才显式重置。
- **旁白全中文**：p、q、age、n 只出现在板上等宽字体里，旁白说“第一张纸条”“第二张纸条”“年龄那间病房”，`*` 读“星号”，`&` 读“取地址符”；预测题也这样说。好处是字幕里没有单个字母，不会出现 c、o 的字形问题，也避免 TTS 读单字母。
- **范围**：不讲指针运算、数组与指针、`NULL`、多级指针、函数指针等；`int* b, c;` 的声明陷阱本机实测属实（`c` 只是普通整数，`sizeof` 为 4），但超出本课范围，只记在调研里。
- **错误例子如实写成警告**：漏星号（`p = 8;`）和未初始化就解引用（`int *p; *p = 5;`）在 gcc 13.3 的 `-Wall -Wextra` 下都只是警告（编译通过），加 `-Werror` 才变成错误；旁白说“实测在打开常用警告选项的情况下”，不说“一定报错或崩溃”，两种输出原文都存进 `validation/`；两个例子都只编译、不运行。
- **内存图画法**：病房＝外框 + “病房”标签 + 一个数字单元格（名字用拉丁字母）；纸条＝小格子，格子里写“age 的地址”；箭头用 memory 的 `arrows`；“改指别处”＝旧箭头加 `until`，再画新箭头，同时 `setv` 改格子里的字。
- **取帧看版面**：用锚点短语时间加书写时长之后、板结束前 0.5 秒之前的时刻；拼图里“写到一半”的帧要重取，不要据此判断版面。

### 2.13 把两堂课接起来：指针与数组（第 8 课）

- **选题**：回答前面留下的悬念——第 3 课说“数组传参要另外交个数”，却没讲为什么；第 7 课刚讲完指针变量。用“同一个 `sizeof`，主函数里算出 5，函数里却得到纸条的大小”做认知冲突，再回头讲 `p + 1` 与 `a[i]`。
- **左右对照**：板分左右两半——“主函数里”（整排病房，`sizeof a` 为 20、`sizeof a[0]` 为 4，20 ÷ 4 = 5）和“函数里”（只有一张纸条，`sizeof arr` 为 8，8 ÷ 4 = 2 打叉），缩略图就取这一帧。
- **`p + 1` 的讲法**：纸条上的地址换成下一间病房；每间一样大，所以是“下一间”，不是“加一个字节”；序号从零数起（不走＝第一间，加一＝第二间，加二＝第三间）；“相邻两间相隔四个字节”只在旁白里说，板上只写“相隔一个整数的大小”。
- **旁白无英文字母**：`sizeof` 说“量大小的运算符”，`a[i]` 说“数组名方括号序号”，`*(a + i)` 说“在数组名加序号的外面写星号”；`a`、`p`、`q`、`r`、`d` 只在板上等宽字体里。
- **搜索说法也要核对**：cppreference 原页没有讨论 `a[i]` 与 `*(a + i)` 的等价，结论来自本机实测（5 个元素逐个相等）；脚本的 `claim_check` 里写明依据。
- **gcc 比预想更爱警告**：对数组形参用 `sizeof` 在 `-Wall` 下就是警告（`-Wsizeof-array-argument`）；即使写成 `int *arr`，`sizeof arr / sizeof arr[0]` 还会有 `-Wsizeof-pointer-div` 警告。所以正确例子用 `int *arr` 只量 `sizeof arr`，要确认算式结果（`count=2`）就关掉该警告单独运行并存档。越界读取 `int *p = a + 5; return *p;` 在 `-O0` 下没有任何提示，`-O2` 才有 `-Warray-bounds`，旁白只说“编译器不一定拦住你”。
- **内存图**：一排五间病房＝5 个单元格（`addr` 标序号，只有第一格带数组名）；`p + 1`＝旧箭头加 `until`、`setv` 改纸条格子里的字、再画新箭头；越界＝一个值为“?”的单元格加“走出去了”标签，箭头和它一起设 `until`。

### 2.14 选题复审与“带回来”：函数返回值（第 9 课）

- **选题复审（用户要求时做）**：原推荐《字符串与 `char *`》被降级，理由三条：与已发课程重复（第 4 课字符数组、第 8 课 `sizeof` 对照）；核心新结论“不能改字符串字面量”是未定义行为，不能像前几课那样用真实输出支撑，错误例子又只编译不运行；解释它要用到只读内存，超出“病房 / 纸条”比喻。复审标准：**是否重复、核心结论能否实测、是否需要超范围概念**；换成系列里一直缺的“带回来”（函数返回值）。
- **“传进去”与“带回来”对称**：传进去抄一份，带回来也抄一份；`return` 带回的是结果单上抄来的值，局部变量的值可以带出，一个函数一次只能交回一个值。
- **局部病房被拆**：函数是一次出诊，局部变量是临时搭的病房，函数一结束就拆（回扣第 2 课克隆体消失）。返回局部变量的地址＝带回一张指向已拆病房的“悬空纸条”。
- **未定义行为的讲法**：不运行、不演示崩溃，旁白只说“读出来的数没有任何保证”，依据 cppreference 打开过的原页（生命周期之外访问对象是未定义行为）；搜索摘要里“运行时一定报错”的说法过于绝对，在研究报告里标明、课里不采用。
- **gcc 警告**：返回局部变量地址或局部数组名（`-Wreturn-local-addr`）在不加任何警告选项的默认设置下就有，加 `-Werror` 变错误，`-O0` 与 `-O2` 一样；忘写 `return`（`-Wreturn-type`）要 `-Wall` 才有。三个错误例子各存默认警告、`-Werror`、`-O2` 的原文。
- **正确做法**：由调用者先准备病房，再把地址传进去（回扣第 3 课），这样还能带出不止一个结果；`static`、`malloc`、返回结构体、递归都不讲。
- **两区版面**：一个“函数里”外框、一个“主函数里”外框，中间一个结果单小格子。复制用 memory 的 `from`，**只能在单元格创建时指定**，所以接收值的单元格要在复制发生的时刻才创建（`r` 在 `t_recv` 时创建并 `from` 结果单）；“拆掉”用 `dim`，需要消失就给 `until`，要留下灰框就不给；指向灰框的箭头不给 `until`。
- **小格子的宽度**：`small=True` 的单元格里写“local 的地址”这类字，宽度至少 215，否则溢出到外框上。

### 2.15 把规则接到新结构上：二维数组传参（第 10 课）

- **选题复审三条标准照用**：不与已发课程重复；核心新结论能用真实输出支撑（`sizeof a[0]`＝12、`a + 1` 与 `a` 相差 12 字节、省两个维度的真实编译错误）；不需要超范围概念（只用 `int a[][3]`，不讲 `int (*p)[3]`）。
- **比喻**：二维数组＝一排大病房，每间大病房里有几张床；列数＝每间有几张床，行数＝有几间。`a + 1` 走过一整间大病房（回扣第 8 课 `p + 1`），不是下一张床。
- **为什么列数不能省、行数可以省**：编译器要知道一间大病房有多大，才知道加一走多远；行数只说一共几间，不影响走多远。搜索摘要里的寻址公式（`b + 列数 * i + j` 不含行数）用本机实测核对（`a[1][2]` 与 `*(flat + 1 * 3 + 2)` 都是 6）。
- **真实报错自带解释**：省两个维度是编译错误，gcc 的 note 原文写着“多维数组必须给出除第一维外所有维度的大小”，旁白直接引用；列数不一致、传给 `int *` 是 `-Wincompatible-pointer-types` 警告，gcc 13.3 默认就有（gcc 14 起是错误），自审里要标明版本。
- **边界写法只作演示**：按一维顺序读二维数组（`(int *)a`）严格按标准有争议，旁白只说“实测读到 1 2 3 4 5 6”，不说它是标准保证的写法；cppreference 原页也没有明说多维数组连续存放，如实写进 `claim_check`。
- **版面**：右侧两间大病房（两个外框，每个 3 个床位单元格，序号标在格子下）；“一长条”用六个由床位 `from` 复制出来的单元格排成一行，不移动原床位；纸条放在大病房**左边**，箭头水平指向床，避免从下方穿过其他床位。
- **正确例子要躲开自己的警告**：函数形参里的 `sizeof a` 会触发警告，正确例子只量 `sizeof a[0]`（元素类型已知，不警告）。

### 2.16 先研究再选题、难点讲法与通俗度：动态内存分配（第 11 课）

- **策划阶段先研究、批准计划再建项目。** 用户说“策划下一个知识点”时，在计划模式下研究并写计划文件。用户随口提的题目只是想法，要按标准评判，可以否定：第 11 课先拿“选择排序 / 链表”做候选，被用户要求先研究三件事——能否和前十课完美衔接、难点用什么方法让学生看完会、讲得是否通俗。结论：选择排序只接得上第 1 课（等于从指针这条线退回去）；链表缺“申请内存、空指针”两个前置（第 7–10 课一直列为范围外）；最合适的是第 9 课直接留下的问题——函数里临时病房会拆，怎么让函数准备好病房交回来——所以做动态内存分配，链表放到后两课。
- **选题四条标准**（在 2.14 的三条复审上加一条）：①前置讲过没有（`grep` 已发脚本旁白与 `out_of_scope`）；②能不能从最近一两课自然长出来（拿上一课留下的问题当钩子）；③新东西是不是只有一两个（本课只有申请函数、归还函数、空纸条三个）；④核心结论能不能实测（本课全部可编译运行）。
- **课前研究要核对**：教材顺序（谭浩强第五版 8.8 动态内存分配在 9.4 链表之前，只看到目录）；现有教程缺什么（四个已打开的页面都没解释“为什么申请来的内存能活过函数”，也没有忘了归还的具体账目）；学生难点研究（只见摘要要标明；转述要对原文——论文摘要说的是“不了解 malloc 返回值要不要转换类型”，我一度写成“不懂 malloc”，后来更正）。
- **难点怎么讲：每课都做一张“难点 → 学生怎么想 → 讲法 → 实测证据”表。** 第 11 课七行：申请来的病房为什么函数结束了还在（并排对照，只差声明一行）；申请多大（几间乘每间多大，预测题）；纸条只知道第一间（量纸条是 8，间数自己记）；申请不到（空纸条，先检查）；归还以后（纸条要自己擦，不运行没有保证的写法）；忘了归还（运行检查报告）；刚申请回来里面有什么（没有保证，先写后读）。
- **七个做法**：前置单独讲（预训练）；先错后对、左右并排只差一行；中途先猜后看（s3 新增一次 3 秒预测；教学研究的结论是学生参与比动画本身重要，来源只见摘要）；步骤口诀固定在板角（“申请—检查—使用—归还”，讲到哪步亮哪步）；跟着画；看完就动手（课后练习）；拿学生最常犯的错当例子。
- **通俗度自查写成脚本断言**（`build_script.py`）：平均句长 ≤24 字、最长单句 ≤50 字（句子以“。？！”切）、旁白英文字母与阿拉伯数字为 0、难词表（未定义、堆、栈、解引用等）命中为 0、每个新词在旁白里有一句大白话。首稿平均 24.5、最长 65 被挡住，按句号拆句（不改字数）后 20.0、47。审阅页顶部放自查表，用户一眼能看。
- **旁白不读代码词**：malloc 说“申请函数”，free 说“归还函数”，NULL 说“空纸条”，sizeof 说“量大小的运算符”；类型转换说“多写一个括号，里面写上类型”；“动态内存分配”“内存泄漏”这类书上的名字各只说一次。
- **free 不改你手里的纸条**：用值传递推理（归还函数拿到的是抄件），不运行、不打印归还之后的指针（标准规定释放后指针值不再确定）；旁白只说“纸条还在、它指着的病房已经不是你的了、顺着它读写没有任何保证”。依据 cppreference free 页（空指针什么也不做；归还两次、归还后访问未定义）；存储期依据 cppreference storage duration 页（分配存储期的存储按请求分配和释放）。malloc 页没讲存储期和类型转换，“不转换也能通过编译”只来自实测。
- **实测发现与计划不一致（别凭印象写）**：gcc 13.3 下，局部数组名交回默认就有警告；还了又用不加选项没有提醒、`-Wall` 就有 `-Wuse-after-free`（归还两次也被它抓到）；对局部变量 `free` 默认就有 `-Wfree-nonheap-object`；忘了归还、不检查空纸条、`malloc(3)` 在 `-Wall` 下都没提醒，`-fanalyzer` 才有，且不检查空纸条在 `-O2` 下分析器漏报（GCC 文档写明分析器既不 sound 也不 complete）。每个提醒都要编译实测，各选项与 `-O0/-O2` 都存原文再写。
- **泄漏不是没有保证的写法，可以运行**：`-fsanitize=address` 本机可用，报告 `12 byte(s) leaked in 1 allocation(s)`（12＝3 个整数）。程序自己的 `printf` 输出在重定向时会丢（检查工具以 `_exit` 结束，缓冲没刷新），板上只放 SUMMARY 一行。还了又用、归还两次、归还局部变量仍只编译不运行。
- **版面语言**：“函数里 / 医院 / 主函数里”三种框用 `zone()`（带 `until` 淡出，不要用盖底色的矩形去“擦”）；纸条是小格子，竖直箭头要求两个格子之间至少 88 像素；归还＝病房变成空框（`setv` 置空），擦成空纸条＝纸条 `setv` 置空加斜杠，抄件＝新单元格带 `from`；s3 左右并排各一套代码和小框；口诀在 s2 逐步写出，之后每板用一条灰色长条加金色下划线标当前步骤；强调单元格用 `box()` 红框，红圈只圈数字和短词。
- **课后练习（第 11 课起）**：发布包里加 `_课后练习.txt`：读程序先猜再运行 → 改一处 → 找错（A、C 只编译，B 可运行）→ 自己写。程序在 `code/exercises/`，`scripts/make_exercises.py` 把代码和答案生成文本（去掉会泄题的注释），答案全部来自 `-Werror` 的真实运行；`docs/whiteboard_release_pack.py` 复制它并在目录里说明。“学会”的标准：能写出申请—检查—使用—归还；能说清申请来的病房可以交回而临时病房不行；能认出还了又用和忘了归还。
- **核对**：本课静默 3 次，静默检测应有 3 处问答停顿加结尾；带片头的成品开头还有 2 秒封面静音。

### 2.17 压缩新东西、术语陷阱与链表初识（第 12 课）

- **选题四条标准照用，新东西要压缩到三个。** 链表本身有很多内容（插入、删除、尾插、动态结点），第 12 课只留“卡上装下一张的纸条、顺着走一遍、头插的顺序”，并限定为主函数里的普通变量（不用 malloc、typedef、指向头纸条的指针）；其余放到第 13 课及以后。
- **术语陷阱：“静态链表”一词在不同教材里意思相反**（C 语言中文网：数组加游标；谭浩强教材目录里也有“静态链表”，只核实了目录，正文含义未核实），课里不用，把它写进脚本的禁用词检查，只说“三张卡连起来”。凡是要对应教材的词，先查教材目录和至少一个打开的页面，别凭印象。
- **难点表（难点 → 学生怎么想 → 讲法 → 实测证据）**：为什么不用数组（数组头插挪 3 次，卡只改两张纸条）；卡里装什么（装纸条，整张卡装进去是编译错误 `field ‘next’ has incomplete type`）；连起来、走一遍（打印 1 2 3）；头插顺序（先连后面，再改前面；反了限定走 6 步全是 9，旧三张卡没人指着）；遍历条件（`p->next != NULL` 只打印 1 2）；忘了给最后一张写空纸条（gcc 在默认、`-Wall -Wextra -Wpedantic`、`-fanalyzer` 下都没有提醒，读它没有保证，只编译不运行）。
- **能运行与不能运行的界线**：顺序反了会绕圈，但把遍历限定为最多 6 步，输出确定、不是没有保证的写法，可以运行并展示；读未赋值的 `next` 才是没有保证的写法，只编译。每次先问“这个例子有没有读没有保证的值”。
- **版面语言**：一张卡＝外框 + id 格（name id）+ 下一张纸条小格（name next，small）；头纸条与走路纸条是独立小格，走一遍用 `setv` 换字再换箭头，旧箭头加 `until`；卡“丢了/走不到”＝`dim` 变灰；自指箭头用三段 `stroke`（先上、再横、再下箭头）画，起止点避开格子名字所在的正中上方；竖直箭头要求两个格子之间至少 88 像素，走路纸条放在卡下方 y≈640、卡的 y 差不超过 40；三张卡故意高低错落以画出“不要求紧挨着”；s8 预测题的链用等宽文字（`head → 1 → 2 → 3 → NULL`）表示，答案出现时换成新链。
- **画面细节**：带 `addr` 的格子下方约 34 像素是地址标签，别在下方 60 像素内放说明字；单元格名字（id、next、old）只用拉丁字母。
- **结尾板的笔迹要早写**：笔迹按估计字幕时间触发，越靠后误差越大（本课结尾最后一句回顾比旁白晚约 2 秒，板上只在最后 0.5 秒才写完）。末尾板的最后一两句要提前触发、缩短书写时长，不要放“旁白说完才写”的大字；渲染后一定看最后 3 秒的几帧。
- **流程教训**：退出计划模式的返回里没有明确的批准内容时，不是批准；把计划摆在对话里，只认用户在对话里的口令；已经做了的东西如实说明，让用户决定保留还是删除。
- **课后练习**：沿用第 11 课的做法；练习里会泄题的代码提示语（程序里的英文说明、注释）要换成中性输出，另存为 `ex3a.c` 一类的练习专用文件并真实运行，答案才和给学生的代码一致。

### 2.18 先错后对、三区版面与逐张演示：动态链表（第 13 课）

- **新东西压到三个**：函数里申请一张卡并交回；函数里改头纸条改的是抄件（第 2 课克隆门），要交回新的头纸条、主函数接住；整串归还先存下一张再还当前这张。不讲指向头纸条的指针（两个星号）、尾插、删除。
- **先错后对用同一版面**：s3（错）与 s4（对）三个框（函数里、医院、主函数里）和卡的位置完全一致，先错版本能运行：没交回新头时主函数仍打印 1 2 3，地址检查报告一次申请没归还；先还再读只编译，`-Wall` 就有 `-Wuse-after-free`；申请后不检查只有 `-fanalyzer` 才提醒。
- **箭头算法决定摆位**：`memory` 的箭头在两格中心 |dx| ≥ |dy| 时走水平（终点在目标格左/右边缘，从右边来的箭头会穿过目标卡的 next 格），否则走竖直（起止各缩进 44 像素）。要避免穿过格子，就把出发格摆在目标卡的正上方或正下方，让 |dy| > |dx|。“函数里”框因此缩小到只放抄件，“医院”框只放新卡并摆在第一张卡正上方。
- **逐张演示用多个小格轮流出现**：走路纸条 p 和存下的 next 各画在主函数框下方、对准一张卡（竖直箭头），用多个小格按顺序出现与消失，别让一个格子带着长箭头跨过几张卡；少还一张之类的局部演示放在框外右上角的三个小格，不污染主链。
- **按旁白锚点定时，先打印锚点时间**：逐张归还首版按整段平均分配，比旁白早约 2 秒；改为“存起来”时出现存下的纸条、“再还这一张”时清空第一张，其余随后。写多步动画前先把相关锚点时间打印出来看间隔。
- **报告行要在“实测”之前开写**：地址检查的 SUMMARY 行有五十多个字符，等旁白说“它说”才开始写根本写不完；从“实测”开始写，下划线和中文翻译留到旁白说出结论时。
- **板上代码要与实测程序一致**：板上用走路纸条 `p` 逐张归还，而实测的 `free_all` 用的是 `head`，所以另写 `free_walk_p.c` 并实测（`-Werror`、-O0/-O2 通过，检查无报告）。
- **单帧渲染约 5 秒一帧**，是检查版面最便宜的办法：先批量出一轮关键帧，逐块修，再出样片。
- **课后练习**：4 类题（读程序两道、找错四道含两道只编译、自己写一道）；练习里的函数名也会泄题（`add_lost`、`free_all_wrong`），要换成中性名字再放进练习。

### 2.19 删除一张卡：停在前一张、先绕过再还（第 14 课）

- **选题**：第 12、13 课范围外都写了删除；第 13 课整串全还，自然问“只还一张”。新东西压到三个：走路纸条停在要删那张的**前一张**；**先绕过再还**；删第一张没有前一张，要改头纸条，所以**交回新头**。先做删除、后做中间插入：“停在前一张”只讲一次，第 15 课直接复用（与 learningc 的“插入在前、删除在后”相反，因为头插已经讲过）。
- **先错用图讲**：走到要删的那张就还，前一张的下一张纸条仍指着已还的卡；走路纸条只能往前走，回不到前一张，也改不了那条纸条。再用“前一张”这个名字（旁白里配一句“指着它的那张卡，叫前一张”）。
- **难点表（难点 → 学生怎么想 → 讲法 → 实测）**：为什么停在前一张；绕过（没有纸条指着它）；先绕再还（还了它的下一张纸条不属于你）；删第一张（改头纸条、交回新头）；只绕不还（卡还占着病房，报告一次申请没有归还）；没找到（走到空纸条，原样交回）。
- **每个错法各测各的，不要互相推断**：只绕不还、只会处理中间（删第一张什么也没删）可运行；先还再绕 `-Wall` 有 `-Wuse-after-free`；只还不绕默认和 `-Wall` 都没提醒，只有 `-fanalyzer`；删第一张没交回新头 `-Wall -O0` 没提醒、`-O2` 有、`-fanalyzer` 有。旁白只如实说“有的选项提醒，有的不提醒”。
- **版面**：只用“主函数里”一块框，“函数里”框只在 s5 删第一张时出现。走路纸条 p、要还的 gone、存下一张的 next 都画在卡下方 y=820，各自对准一张卡的竖直箭头，用多个小格轮流出现；绕过用手绘折线箭头走卡上方空带（y≈488，主函数框顶 450 与卡顶 520 之间）绕过要删的卡，指向后一张卡的上沿。s4 开头直接画出已绕过的状态（与 s3 结尾一致）。标签放在竖直箭头旁边，不压箭头；问句行不要和 y=820 的小格叠，小格用完就给 `until`。
- **渲染器坑**：memory 的箭头字典里 `"until": None` 会变成 JSON null，渲染器当 0 处理，箭头整条消失（小格在、箭头没有）。没有 until 就不要写这个键。
- **缩略图选帧**：笔迹按估计字幕时间触发，板子最后一秒常有写了一半的话；先渲染几个候选帧并排看，选板上字都写完的帧（本课选了 s3 的最后一帧）。
- **课后练习**：读程序两道、找错四道（两道可运行、两道只编译）、自己写一道；函数名用中性名字（`take_out`、`cut_after`）；泄漏练习要把其余的卡整串还掉，只留要演示的那一张，否则 LeakSanitizer 把没还的整串都报告（实测 4 次申请），答案就和“只漏了一张”对不上。
- **板上代码一律有对应的实测程序**：`code/delete_func.c` 的 `remove_card` 就是 s7 板上的函数，逐行一致。

### 2.20 按顺序插入：找位置、两步顺序、三种位置（第 15 课）

- **选题**：第 14 课范围外写了“中间插入（第 15 课）”，反过来最自然。新东西压到三个：找位置（走路纸条停在“下一张比新卡大、或是空纸条”的前一张）；两步顺序（先连后面，再改前面，第 12 课口诀重讲，因为第 13、14 课几乎没再提）；三种位置同一个函数（最前要交回新头、中间、最后，空链子新卡直接做第一张）。不单独做“在某张卡后面插入”（比第 14 课还轻），也不点名“插入排序”。
- **先错用图讲**：直接头插得 5 2 4 6，没排好（可运行）；再让走路纸条一步步走，每步看“下一张的编号比新卡小吗”。条件是“先看有没有下一张，再看它的编号”，这一点单独成一个错误（先读编号再看是不是空，只编译）。
- **难点表**：新卡该排哪（头插没排好）；停在哪（停在前一张，停过头得 2 4 6 5）；条件里谁先谁后（读空纸条的编号没有保证）；两步顺序（反了：新卡自指，限定 6 步打印 2 4 5 5 5 5，卡 6 没人指着，报告一次申请没有归还）；插到最前（改头纸条，交回新头）；插到最后和空链子（新卡的下一张纸条是空纸条；头纸条是空纸条）。
- **每个错法各测各的**：头插、两步反了（限定 6 步）、停过头、没处理比第一张还小（2 1 4 6）都可运行；先读编号再看是不是空默认、`-Wall`、`-Wall -O2`、`-Wall -Wextra -Wpedantic` 都没提醒，只有 `-fanalyzer`（null-dereference）。
- **版面**：沿用第 14 课只用“主函数里”一块框；新卡画在框上方的空带里（新卡在 4 与 6 的正上方时，两步用竖直方向的箭头就够，不用折线）；走路纸条小格画在卡下方 y=820；s7 两列等宽代码字号 26，第二列 x=1010，第一行很长（55 个字符），字号 28 时会碰到第二列。
- **LeakSanitizer 的演示**：两步反了之后卡 6 没人指着，程序末尾要把能走到的卡先还掉、只留卡 6，报告才是“一次申请”；否则会把整串都算没还。
- **练习**：读程序两道、找错四道（三道运行、一道只编译）、自己写一道；函数名用中性名字（`put_in`、`put_after`）；练习程序里没用到的函数会被 `-Werror` 挡住（unused-function），写完逐个编译。
- **流程**：渲染完成前用户说了“样片通过”“成片通过”，都先核对再请用户再说一次；这是第 14、15 课都出现的情形，别提前进入下一步。

### 2.21 递归：函数自己叫自己（第 16 课）

- **选题与补漏顺序**：用户让“查缺补漏”。做法：把十五课旁白里的关键词统计一遍（递归、全局变量、static、typedef、结构体数组、文件、函数指针等都是 0 次），再对照教材章节与各课 `out_of_scope`（递归被推迟了 5 次）。用户 2026-10-06 确认路线：**16 递归 → 17 变量的一生（局部、全局、static）→ 18 栈（链表头插删头）→ 19 结构体数组与 typedef → 20 文件读写 → 21 函数指针**；前十课课后练习暂不补。
- **新东西压到三个**：函数里再叫自己，每叫一次出一位新医生（新临时病房，回扣第 9 课）；到头了就停（走到空纸条答零）；等它回来再接着做（先打印后叫得 2 4 6，先叫后打印得 6 4 2，只换两行）。不讲尾递归、效率、斐波那契汉诺塔、栈溢出；**旁白不说“栈”“调用栈”“基准情形”**（“栈”留到第 18 课）。
- **讲法**：先让一位医生去数、他再叫下一位；“一层层问、一层层答”用卡下方叠着的四位医生小格——红箭头向右问、绿箭头往回答，每位旁写 2+1=3、1+1=2、0+1=1、0；中途 3 秒预测“最后一位医生拿到空纸条答几”，结尾两道预测题（1 3 5 7 9 倒着打印、数空链子）；板角口诀“到头就停，往后交，等它回来”。
- **实测（gcc 13.3，-Werror，-O0/-O2 一致，检查工具无报告）**：数卡 2 4 6 得 3、空链子 0、一张卡 1、1 3 5 7 9 得 5；正着 2 4 6、倒着 6 4 2、9 7 5 3 1；到头答一（`return 1`）数出 4；写成 `p->next == NULL` 就答零数出 2（空链子不运行，会读空纸条）。**两个“永远叫不完”的版本只编译不运行**：忘了到头就停——默认没有提醒，`-Wall` 有 `-Winfinite-recursion`（-O0、-O2、-Wextra 都有），`-fanalyzer` 没有；不往前走（交出去的还是自己这一张）——默认、`-Wall`、`-Wextra` 都没有提醒，只有 `-fanalyzer` 的 `-Wanalyzer-infinite-recursion`。板上如实写“常用的警告选项不提醒，只有专门的分析选项才会提醒”。
- **版面**：沿用只有“主函数里”一块框的写法；先错后对（忘了到头就停、不往前走、到头那句写错）；到头那句写错的两个版本可以运行（数出 4、数出 2），“叫不完”的两个只编译，各测各的。
- **练习**：练习一、二读程序先猜再运行，练习三找错（五个小题：三个可运行、两个只编译），练习四自己写；函数名用中性名字，练习文件只留用到的函数。
- **本课的教训（已写进 4.4 与踩坑表）**：①s4“实测”行把中文标签和数值写在同一个等宽 `write` 里，成片出现方块字——**等宽字体没有中文字形**，早就在踩坑表里，这次又犯了，所以现在有 `docs/whiteboard_lint.py` 在渲染前拦；②用户已经说了“成片通过”，核对时才发现缺陷——如实说明、重渲、重新核对，并请用户重新说“发布通过”；③28 帧稀疏抽样漏检，改为 4 秒一帧加每个问答时刻的帧；④缩略图取帧要等 s4 四行实测写完（158.0 秒）；⑤渲染完成前说的“样片通过”“成片通过”仍不当批准。

### 2.22 变量的一生：局部、全局、static（第 17 课）

- **选题**：补第 9 课推迟的 static；十六课旁白里“全局变量”“作用域”“生存期”都是 0 次，而“临时病房”66 次、“医院病房”88 次，铺垫足。**钩子**是第 16 课的悬念：想数一数递归一共叫了几位医生，每位各数各的，每位都只数到一。新东西压到三个：全局变量（大厅病房）、static 局部（记得住的临时病房）、“谁看得见”和“活多久”是两件事。不讲 extern、多文件、register、auto、文件私有的 static 全局。
- **讲法**：板角常驻一张三列小表（病房 | 谁看得见 | 活多久），s2–s5 逐行增加；三种计数器并排，每叫一次在下面写一个小格；第 7 段用一句话澄清“函数前面的 static 是另一回事”（每课板上代码里都有）；口诀“看写在哪，看加没加静态，能传别用大厅”。旁白里 static 一律说“静态”，不说“静态链表”，也不用栈、堆、作用域、生存期。
- **实测（gcc 13.3，-Werror，-O0/-O2 一致，asan 无报告）**：三种计数器叫三次依次 1 1 1、1 2 3、1 2 3（叫四次到 4）；递归数卡全局计数：2 4 6 叫 4 位、空链子 1、一张卡 2、1 3 5 7 9 叫 6；全局与 static 局部默认零；两个函数交叉改全局，先加后乘 6、先乘后加 4；`static int n = 0;` 得 1 2 3，每次再写一遍零得 1 1 1；外面直接写 static 变量名编译错误 `‘n’ undeclared`；局部遮住全局（里面 3 外面 8，只有 `-Wshadow` 才提醒）；读未赋值局部：最直接的写法 `-Wall` 提醒 `-Wuninitialized`，条件里才赋值的写法默认、`-Wall`、`-O2`、`-Wextra` 都不提醒，只有 `-fanalyzer`（只编译、不运行）；函数前的 static 是文件私有，另一个文件调用会链接报 `undefined reference`。
- **求值顺序陷阱（新）**：同一条 `printf` 里既调用会改全局的函数、又读这个全局，gcc 先读旧值，打印 0 而且没有任何提醒。板上代码和练习一律**先把结果存到变量（用 `report()` 之类的小函数）再另起一句读全局**。
- **版面与时间**：第 17 课旁白实测 361.24 秒，预估 391.2 秒，短 7.7%，因为纯说话约 0.224 秒/字（单句样音 0.228，也偏快）；贴近 360 秒下限，按接受处理。三处静默各约 3.1 秒（70.37、321.21、337.65 秒起），答案最早出现时间 73.44、324.24、340.68 秒。
- **事实引用**：计划里把“传地址”写成第 3 课，实际是**第 2 课**（第 3 课是数组传参）；脚本里引用别课内容前，用该课项目的 `script.json` 对一遍。
- **缩略图**：取 231.1 秒；更早的帧会露出右侧“error:”原文写了一半。
- **流程**：渲染前先 lint 0 错 0 警告，再 `--contact` 看 K1–K8；成片按 4 秒一帧共 91 帧加 18 个问答时刻帧逐张看；渲染完成前没有人说“通过”。本课用 `--local` 渲染，没有走远程通道（用户要在第 17 课全部完成后单独做整课远程实验）。

**每个门的做法**

- 门之前只给“需要用户决定的事”，不要长篇。一个门一次批准，不合并。
- 写检查点：门控阶段先 `awaiting_human`，用户批准后再写 `completed`（`human_approved=True`）；前置阶段必须都已完成。
- 决策记录（`decision_log.json`）只追加，不改历史；类别要用 schema 允许的枚举。
- 门后发现问题：小改并重走该门（第 3 课的脚本和场景计划都是批准前经对照清单修订后再交审），改动写进审阅页的“相对上一版的修改”。
- 自审记录 `round` 在 schema 里最多到 2，重审时标 2，并在 `metadata.previous_round` 指向上一版记录。

**时间与成本参考**

- 单帧静态图渲染约 5 秒，逐段抽帧看版面比直接渲染整片省很多时间。
- 30 秒样片约 4 分钟；整片 5.5 分钟约 43 分钟、8 分钟约 60 分钟（第 3 课 467 秒用了 3624 秒）。
- 素材阶段的样片：先出一张最难的插图 / 姿态图样图和 s5 一类关键句的样音（约 15 秒），确认后再批量；整段配音实测语速后，把全课时长从估计回填为实测。
- 局部重渲染再拼接：帧范围渲染 + ffmpeg 重编码一次 + 音轨直接复制，用 md5 与逐帧 PSNR 验证。

**环境限制（本机：4 核、无 GPU、Node 18）**

- 只能用 Remotion；HyperFrames 需要 Node ≥22，Ink Theater 只跑在 HyperFrames 上，均不可用。
- Google TTS 不可用（密钥 401），用 DashScope `qwen3-tts-flash`（Cherry 女声）。
- Pixabay 音乐抓取返回 403，十门课都不加背景音乐（用户可自备曲目）。
- 没有本地语音识别，字幕时间无法用转写核对。

### 4.4 分块渲染、多进程并行、渲染前检查、关键时刻总览与远程渲染（第 16 课起，工具都在 `docs/`、`remotion-composer/render-tools/`、`tools/video/`）

**为什么要多进程**：一个 Remotion/Chrome 进程内部有串行瓶颈，标签页（`--concurrency`）开到 2 以上没有收益；要用满核必须多开进程。`render_chunks.mjs` 的 `workers` 就是并行进程数（父进程打包一次、子进程共用，各自一个 Chrome）；每个块拆成若干 ≥120 帧的部件并行渲，再用 `ffmpeg -c copy` 拼回块（部件流参数不一致时自动改重编码拼接）。本机默认 `核数/2` 个进程×2 标签页。

**工人失败时快速失败**：`render_chunks.mjs` 父进程任一子进程失败（含被信号杀、创建子进程失败）就打印 `worker N failed (exit CODE)`（格式固定，渲染机 agent 靠这一行判断）、向所有子进程发 SIGTERM、5 秒后 SIGKILL、7 秒后硬退出（码 1）；收到 SIGTERM/SIGINT 则退出 143；子进程自己也处理 SIGTERM 与未捕获错误并以非零码退出。原来父进程会无限等不响应的子进程，远程作业因此挂着不结束（第 17 课后的整课远程实验里 K2 就是这样）。

**远程渲染的时间账（第 17 课后实测，第 16 课整课 11300 帧）**：整课自动模式 284 秒 → 259 秒（本机基准 1625 秒）。分解：排队 18 秒、渲染窗口约 214 秒、取回装好 10 秒、拼接 1 秒。我们这一侧做了四件事：并行排队与轮询、把所有待渲染分块一起切成约 30 段按帧数均衡分给 4 个作业（`remote_groups`）、下载与渲染重叠、旁白 AAC 编码（单核 33 秒）改为渲染期间后台做、结尾只拷贝。**前三件事单独看没有缩短总时间**（渲染窗口才是墙，约 55 帧/秒，worker 从 16 加到 32 不再变快），真正省下来的是 AAC 那 33 秒。分段长度：不短于 120 帧最快（`--min-part` 可调）。再快要靠渲染机查清平台期的原因（见 `docs/remote-render-agent-brief-v5.zh-CN.md`）：**原因是渲染机的 CPU 配额限流**（双路 48 物理核/96 逻辑 CPU，4800% 只允许每秒 48 个 CPU 秒，w24/w32 约 59%/71% 的周期被限流），配额放到 9600% 后整课服务内 206 秒 → 144–147 秒，我们这边端到端 **259 秒 → 203 秒**（排队 16、渲染窗口 25–178 秒、取回装好 17、拼接 1；逐帧 PSNR 平均 53.07、最低 46.02 不变）。回滚命令：`sudo systemctl set-property openmontage-render-agent.service CPUQuota=4800%`。

**字体确定性**：`remotion-composer/render-fonts/`（DejaVu 8 个字体 + `fonts.conf`，占位符 `@FONTS_DIR@`/`@CACHE_DIR@`）。`render_chunks.mjs` 启动 Chrome 前设私有 `FONTCONFIG_FILE`，所以任何机器字体一致（本机验证与原默认逐像素相同；环境变量确实生效，改配置画面会变）。本机默认开着 RGB 子像素抗锯齿，`fonts.conf` 已显式写出。

**远程渲染（自动选择，用户无感）**：`whiteboard_render.py` 默认 `auto`——先探测反向 SSH 通道（`tools/video/remote_cpu_render.py`，对方渲染机，强制命令协议），通道健康且对方声明 `src_overlay`+`fontconfig_self_managed`（保证画面一致）才用远程，否则**自动回退本机**并说明原因；`--local` 强制本机，`--remote-cpu` 强制远程（不可用就报错，`--allow-drift` 仅供实验）。远程每个板一个作业，全部入队，谁先完成先下载并拼成块；失败的块自动回本机重渲。对方通过 `probe.render_profile`（`gl`、`chromeMode`、`hardwareAcceleration` 等）和 `probe.capacity` 发布最佳配置，调度器随作业下发，`--render-profile '<json>'` 可覆盖做实验。缓存与后端无关（同一个块在本机或远程渲出来都可复用，来源记在 `chunks/<块>.json`）。**GPU 路径**（`angle-egl`、NVENC）像素不会逐位等同 CPU 光栅化，验收分两级：CPU 路径静帧 PSNR ≥ 50 dB，GPU 路径 PSNR ≥ 45 dB 且 SSIM ≥ 0.995。
- 给对方的需求文档：**`docs/remote-render-agent-brief-v3.zh-CN.md`（只读这一份，取代 v1、v2）**；自测包 `projects/_remote_kit/`（`docs/make_remote_kit.py` 生成，对方用 `bench.py` 自己跑基准矩阵与画面对比）；对方回复写到 `docs/remote-render-replies/`；验收脚本 `docs/remote-render-test.sh`（由用户运行，或授权后我们运行；**我们自己直接运行会被权限检查拦下**）。
- 远程渲染的真实状态以最新验收为准（第 1 轮：通道通过，画面差异 37–49 dB，并发 8 不比并发 4 快，并发 16 失败——都已写进 v3 要求）。

**用法与注意**
- 改一块的内容、只重渲那一块；**配音重生成使后面时间整体平移时，后面的块指纹都会变，仍要重渲**（正常）。改了 `remotion-composer/src` 或字体，所有块都会重渲（合成器哈希在指纹里）。

- 旧课（第 1、2 课）手写体里有 `0` 与大写字母，lint 会报错，那是历史写法，不用回头改；第 5、9 课各有一处竖直箭头间隙小于 88（旧规则出现之前），同理。

## 5. 质量验收清单

交付前逐项做，不要只看工具返回“成功”。

```bash
# 1. 基本信息：分辨率、编码、时长、有音频流
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,duration -show_entries format=duration,size -of compact final.mp4
# 2. 响度与峰值（目标约 -16 LUFS，峰值不削波）
ffmpeg -hide_banner -nostats -i final.mp4 -af ebur128=peak=true -vn -f null - 2>&1 | grep -E "^\s+(I|LRA|Peak):"
# 3. 黑帧、异常静音、长时间静止
ffmpeg -hide_banner -nostats -i final.mp4 -vf blackdetect=d=0.2:pic_th=0.98 -an -f null - 2>&1 | grep -c black_start
ffmpeg -hide_banner -nostats -i final.mp4 -af silencedetect=n=-50dB:d=1.5 -vn -f null - 2>&1 | grep silence_
ffmpeg -hide_banner -nostats -i final.mp4 -vf freezedetect=n=0.001:d=8 -an -f null - 2>&1 | grep freeze_
# 4. 抽帧目测（每个内存图状态、logo、字幕）
for t in 6 30 60 100; do ffmpeg -v error -y -ss $t -i final.mp4 -frames:v 1 review_frames/f$t.png; done
```

- **必看**：logo 是否每帧都在；字幕是否与旁白对应；内存图每个状态；标题有没有被遮住；有没有方块字。
- **语音段重合度**：用静音检测得到成片与源旁白的语音段，计算重合比例（前三门课分别为 96.4%、95.2%、95.0%；第 4 课未做这项比对，只核对了静音位置），作为没有语音识别时的替代证据。
- **问答停顿**：成片里超过 1.2 秒的静音应该只有问答停顿（位置对得上 `narration_timeline.json` 的 `question_end`），答案最早出现时间不早于 `answer_not_before`；再加结尾约 1.4 秒的收尾静音。
- **特殊字形**：板上有 0、大写字母、`'\0'` 的课，抽帧确认显示的是等宽数字 0 / 等宽大写 / 等宽 `'\0'`，不是方块，也不是像字母 o 的 `〇`。
- **抽帧用拼图**：第 4 课渲染前后各出 10 张关键帧，成片抽 15 帧拼成一张缩略拼图一眼看完 logo、字幕、字形；缩略图看不清的细节要在报告里写明“没有逐帧放大检查”。
- **缩略图**：先看图再导出，取帧点要在动画画完之后。
- **封面（第 7 课起每课必做，前六课已补）**：统一 16:9 版式，由 `docs/whiteboard_cover_maker.py` 生成——学校 logo（垫深蓝底，否则白字看不见）、红色“第 N 课”序号标签、手写体大标题 + 红线、一行悬念问句、等宽代码小卡片、右侧医生、右上角“C语言白板课”。新课只需在脚本 `LESSONS` 里加一行 `(项目目录, 序号, 标题, 悬念问句, 代码片段)` 再运行；英文、数字、符号一律走等宽字体（手写体会画成方块）。输出 `exports/thumbnails/cover.png`（1920×1080）和 `cover_1280x720.jpg`，并把序号写进 `exports/metadata/metadata.json` 的 `lesson_number`、`cover_path`；总览图 `projects/_covers/contact_sheet.png`，按序号命名的副本 `projects/_covers/cover_NN_<名>.png`。封面与 `thumbnail.png`（成片截帧）并存，不互相覆盖。出图后先看总览图，再放大看 logo 与标题。**嵌入视频**：`ffmpeg -i output.mp4 -i cover_1280x720.jpg -map 0:v -map 0:a -map 1 -c copy -disposition:v:1 attached_pic -movflags +faststart 新文件.mp4`，不重编码、时长与字幕时间不变；用 `-map 0:v:0 -c copy -f md5 -` 对比成片与新文件的视频流和音频流 md5，一致再替换 `exports/video/output.mp4`（`renders/final.mp4` 保持原样，二者字节不再相同）。

**片头封面规则（第 7 课起，用户要求：每课成片开头都有约 2 秒封面）**

- 做法：不重新渲染。成片渲染、核对通过后，在发布阶段运行 `.venv/bin/python docs/whiteboard_prepend_cover.py projects/<课> --seconds 2`：把封面做成 2 秒静帧 + 静音的小片段，编码参数与 Remotion 成片一致（h264 High、`yuvj420p`、30 fps、aac 48 kHz 立体声），再用 concat 拼在成片前面（`-c copy`），同时把封面图作为附加图片流嵌入（取代上一条的单独“嵌入视频”命令）。

- 前六课已于 2026-10-04 统一补上 2 秒片头（每课 +2.021 秒，内容帧差 0.000）。成品集中放在 `projects/C语言白板课_成品/第NN课_课名/`，每课含 `.mp4`、`.srt`、`_封面.png`、`_简介.txt`，另有 `目录.txt` 和同名 zip；文件名避开 `&` 等 shell 敏感字符（第 5 课用“scanf与取地址符”）。新课发布时照此命名并放进同一文件夹。

## 6. 踩坑速查表

| 现象 | 原因 | 做法 |
|---|---|---|
| “大 O”显示成“大口” | 手写体的大写 O、C 是方形字形 | 代码用等宽字体；字幕单字符指定拉丁字体（带手写体回退，否则全角逗号变方块） |
| 输出行中文变方块 | 等宽字体没有中文字形 | 含中文用手写体 |
| 白色 logo 在浅色白板上看不见 | logo 是白色线稿 | 放深蓝圆角底板，不改标识颜色；标题右移避让 |
| 代码块乱序书写时错位 | 未写的行被跳过 | 未写行保留高度 |
| 配音时长读出 44739 秒 | DashScope 的 WAV 头长度字段错误 | 先 `ffmpeg -ar 24000 -ac 1 -c:a pcm_s16le` 重封装再量 |
| 整片渲染 10 分钟就失败 | `video_compose` 默认 Remotion 超时 600 秒 | 传 `remotion_timeout_ms`（如 7200000） |
| 拼接时 ffmpeg 被 OOM 杀掉，成品缺 moov | 同一输入被多次 `trim` 会缓存已解码帧 | 每个片段独立 `-i`，峰值约 1GB |
| `pkill -f "关键字"` 把自己的 shell 杀了 | 命令行里含该关键字 | 按端口取 PID 再 kill，或停后台任务 |
| 试听服务暴露了 `.env` | 在仓库根目录起了 `http.server` | 只绑 `127.0.0.1`、指定专用目录，并 `curl` 验证 `/.env` 为 404，用完就关 |
| Pixabay 音乐 403 | 抓取被拒 | 不擅自换来源，问用户：自备曲目 / 换来源 / 不加音乐 |
| checkpoint 写不进去 | 前置阶段未完成，或门控阶段没有 `human_approved` | 补齐前置阶段；门控阶段先 `awaiting_human` 再 `completed` |
| `edit_decisions` 校验失败 | cut 的 schema 严格，不能带 `type` 等额外字段 | 两份数据：合规的 `edit_decisions.json` 与完整的 `render_props.json` |
| 校验报 `$ref` 错误 | 系统 Python 的 jsonschema 太旧 | 用项目 `.venv/bin/python` |
| Bash 安全分类器偶发无判定 | 瞬时故障 | 重试一次；仍失败先做不需要 Bash 的事 |
| 用户粘贴命令被换行截断 | 终端换行 | 命令写成一行、路径尽量短 |
| `pytest` 缺失 | 虚拟环境里没装 | 只装 `pytest`（开发依赖已列在 `requirements-dev.txt`） |
| 手写体里的 0 像缺字 | ZCOOL 的 `0`、全角 `０` 都是小四边形 | 无字母的板上可用 `〇`；有字母时用等宽数字 0 叠写（见 2.6） |
| 板上的 `〇` 被看成字母 o | 与 a p p l e 同板 | 改等宽数字 0（见 2.6） |
| 改了 `build_edit.py`，下次又恢复成旧样子 | 它是由 `_build_head.py` + `_build_body.py` 拼出来的，重新拼接会覆盖 | 改源文件，再重新拼接；只改产物等于白改 |
| 后台等待命令永远不结束 | 用 `pgrep -f "关键字"` 判断进程是否结束，会匹配到等待命令自己 | 改成检查日志文件里的结束标志，或用 TaskStop 停掉 |
| 校验脚本在系统 Python 里缺依赖 | 系统 Python 没有 PIL / pytest（第 4 课 `build_edit.py` 又栽在 `No module named 'PIL'`） | 一律用项目 `.venv/bin/python`，并设 `PYTHONPATH=.` |
| 决策记录出现重复编号 | 各阶段脚本写死编号，重跑又追加 | 追加前 `dl["decisions"] = [x for x in ... if x["stage"] != 本阶段]`，追加后 `assert len(ids) == len(set(ids))` |
| 把卡本身传给要地址的函数，gcc 是错误还是警告 | 结构体与指针类型不兼容是硬错误（`incompatible type for argument 1`）；`scanf` 漏 `&` 只是 `-Wformat` 警告 | 例子里先实测，板上如实写“报错”还是“警告”，两者都只编译、不运行 |

## 7. 与用户协作方式

- **用中文、回复精简。** 嫌长就做成表或 HTML 页面；重点放在“需要你决定什么”。
- **每个门单独批准**，先出样片再批量；批准前不进入下一阶段。
- **付费调用先说清楚**：调用什么、几次、估价（写“占位估价”）。
- **不编造**：成本、耗时、来源不确定就直说；不用占位物冒充成品（曾有过静音配音 + 空白渲染还报“完成”的事故，用户拿到“没声音没内容”的视频）。
- **独立核对**：交付时列出做了哪些检查、哪些做不到、替代证据是什么。
- **用户提供的密钥**：只写入 `.env`，不在输出、日志、文档里复述；提醒作废重建。
- **看成片的办法**：用户在远程服务器上看不到浏览器，用 `scp` 下载成片，或建 SSH 隧道后访问；隧道容易断，“打不开”先建议重建或直接 `scp`。
- **审批后发现问题**：小改、只重做受影响的部分、告知用户。
- **提交代码**：先在本地保存，推送和开 PR 等用户明确要求；上游是开源仓库时，PR 只带通用改动。
- **保留商用方案**：用户要求新增本地生图只作补充时，新工具独立成文件，不改旧工具；评分里设保守值，避免免费工具在选择器里悄悄压过默认的商用方案。
- **用户中途打断**：用户拒绝某次工具调用后先停下；用户说“继续”再重试同一步，不换路线。
