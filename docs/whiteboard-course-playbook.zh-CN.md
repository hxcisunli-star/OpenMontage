## 0. 一页摘要

**十三条最重要的原则**

1. **一课只解决一个“认知冲突”。** 冒泡排序：为什么反复比较相邻两数就能排好；传参：为什么 `swap` 函数交换不了。
2. **用故事导入，并做一张“故事 ↔ 代码”的一一映射表。** 映射不出来的故事，不要用。
3. **先直觉，后代码。** 每一行代码都要能指回一个已经演示过的动作。
4. **先演示“失败版”，再演示“成功版”。** 对比比单讲成功版记得牢（值传递失败 → 地址传递成功）。
5. **数字和输出都必须真实。** 手算过的例子、`gcc` 真实运行的输出；没实测的数值不要编。
6. **一段旁白配一块白板。** 一屏文字要少，状态要一步一步出现，旁白说到哪、笔写到哪。
7. **数字、代码、公式、内存图用代码绘制；AI 插图只做比喻配图。** 角色用“定妆图 + 垫图”保持一致。
8. **术语先定、全片一致。** 用户更正过的术语（本课只讲两种传参）要写进术语表，脚本、板书、字幕、简介全部遵守。
9. **先出样片再批量，每个门单独批准。** 最难的一段先做配音样片；内存图先渲染静态帧再渲染整片。
10. **交付前独立核对，不信工具自检。** `ffprobe`、响度、黑帧、抽帧目测；做不到的检查要明说并给出替代证据。
11. **系列课沿用同一角色、术语和隐喻。** 写完脚本先对照上一课审查：术语有没有冲突、角色有没有换名、上一课的哪句话要回扣（第 3 课的 v1 就栽在这里，见 2.11）。
12. **场景计划里每个画面事件都带旁白锚点。** 只写估计秒数会让动作比旁白早 3–6 秒；剪辑阶段用锚点短语定位，找不到就回头改计划。
13. **旁白里点名的每个字符、数字、元素，开画前和画面逐一对照。** 第 4 课旁白说“后面的 p、l、e 还在”，实际 apple 的下标二换成终点牌后只剩 l、e；这是画画面时才发现的，只能重生成一段配音。对照表要在脚本阶段做，不要等到剪辑。

**开新课 10 步（速览）**

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 问清受众、前置知识、时长、想用的隐喻 | 需求卡 |
| 2 | 定“认知冲突”与术语表 | 一句话教学目标 |
| 3 | 设计隐喻映射表与边界说明 | 映射表 |
| 4 | 选例子并手算/实测（`gcc` 运行） | 例子与真实输出 |
| 5 | 写 10 段左右脚本（每段 ≤600 字） | `script.json`（门） |
| 6 | 写场景计划：一段一板、图示语言、插图清单、**每个事件的旁白锚点** | `scene_plan.json`（门） |
| 7 | 素材：配音样片 → 定妆图 → 批量配音与插图 | `asset_manifest.json`（门） |
| 8 | 剪辑：锚定时间、抽帧看版面、30 秒样片 | 样片（用户审） |
| 9 | 合成整片并独立核对 | `final.mp4` 与验收记录 |
| 10 | 发布包（缩略图、字幕、章节、简介）→ 用户批准 | `exports/`（门） |

## 2. 重点：如何设计一门成功的白板课程

### 2.1 选题：一课只解决一个“认知冲突”

好的白板课不是“把知识点讲一遍”，而是让学生带着一个疑问进来，带着一个“原来如此”出去。

| 课 | 学生进来时的疑问 | 一句话教学目标 |
|---|---|---|
| 冒泡排序 | 只准比较相邻两个数，怎么能排好整个数组？ | 反复比较相邻两数、大的往右换，每一轮把当前最大的数浮到最右边 |
| 函数传参 | 我写了 `swap` 函数，为什么两个数纹丝不动？ | 值传递改的是副本；把地址交给函数，才能改到原变量 |

**做法**

- 先写出这句“教学目标”，全片只服务它。超出目标的内容（比如传参课里的数组作参数、`const`）放进“后续课路线图”，不塞进本课。
- **写清前置知识和“还没学”的边界。** 传参课假定学生没学指针，所以：`int *px` 只解释成“这个变量里装的是一个地址”，不展开指针运算；指针单元格里写“a 的地址”，不写十六进制。
- 时长按内容定，不按习惯定。传参课原本想 5–8 分钟，实际按“故事 + 门牌号铺垫 + 两版完整演示 + 进阶”估算，成片近 8 分钟。

### 2.2 故事/隐喻导入

**好隐喻的五条标准**

1. **能一一映射**：故事里的每个角色和动作，都对应代码里的一个东西。
2. **有反差**：让学生先“猜错”。克隆门里手术做了，本人却毫发无损。
3. **可画**：能画成简单线稿，笔画不复杂。
4. **可回扣**：结尾能回到同一个故事收束（“你派去手术的，只是克隆体”）。
5. **边界说得清**：明确告诉学生隐喻在哪里失效。

**克隆门案例拆解**

| 故事 | 代码 |
|---|---|
| 本人 | `main` 里的变量 |
| 克隆门 | 函数调用 |
| 克隆体 | 形参（实参的副本） |
| 手术 | 函数里的修改 |
| 手术后克隆体消失 | 函数返回，形参被释放 |
| 医生拿到家庭地址 | 传给函数的地址 |
| 上门手术 | 顺着地址（`*px = …`）修改原变量 |
| 地址纸条是抄来的 | 指针形参本身也是地址的一份拷贝：函数里改 `p` 的指向，外面的指针不变 |

**结构**：故事一（克隆门）→ 故事二（上门手术）→ **揭晓**：把上面的表逐行写在白板上 → 后面所有演示都用故事里的词（“过克隆门”“上门手术”）。

**隐喻的边界（一定要说出来）**：“克隆门只是比喻，比喻的是数据被复制，别把比喻当成真的有人在被传送。”放在进阶段落，防止过度类比。

**反例**

- 隐喻没有收尾：开场讲了故事，后面再不提。→ 结尾必须回扣。
- 把比喻当机制：学生以为“地址传递就是什么都没复制”。→ 用“地址纸条是抄来的”纠正。
- 中文语境的注意：用户原话是“中国人去韩国整容”，脚本里主角用中性名字“小明”，不做国籍刻板化描写，并在提案阶段请用户确认。

### 2.3 课程骨架模板

传参课的 10 段结构可以直接当模板。冒泡排序的 14 段是同一思路（比喻 → 规则 → 逐轮演示 → 规律 → 代码逐行 → 验证 → 复杂度 → 优化 → 总结）。

| # | 段落 | 目标 | 传参课时长 | 字数 |
|---|---|---|---|---|
| 1 | 故事一 | 建立设定、制造反差 | 45 秒 | 208 |
| 2 | 故事二 | 给出第二种情形 | 26 秒 | 124 |
| 3 | 揭晓与映射 | 故事 ↔ 代码对照表 | 43 秒 | 194 |
| 4 | 前置概念 | 变量的“门牌号”、取地址符、真实地址 | 40 秒 | 215 |
| 5 | 失败版演示 | 值传递：代码 + 内存图 + 真实输出 | 83 秒 | 394 |
| 6 | 成功版演示 | 地址传递：代码 + 内存图 + 真实输出 | 86 秒 | 431 |
| 7 | 进阶/边界 | 地址纸条是抄来的；隐喻边界 | 44 秒 | 233 |
| 8 | 对照与选择 | 何时用哪种；回扣 `scanf` 的 `&` | 39 秒 | 226 |
| 9 | 常见错误 | 错/对成对呈现 | 30 秒 | 130 |
| 10 | 总结回扣 | 三句话总结 + 回到开场故事 | 33 秒 | 160 |

**节奏规律（三门课共同的）**

- 每段 30–90 秒；**演示段最长**（80–90 秒），导入和总结最短。
- 单段旁白 ≤600 字（配音接口限制），实际每段 130–430 字。
- 一段只推进一个动作：一个新概念、一个新符号、或一次演示。
- 全片 5–8 分钟对初学者是合适的；超过 10 分钟先删“常见错误”这类可选段。
- **一段一个动作，要拆就拆。** 第 3 课 v1 的 s5 有 449 字，同时讲地址副本、原数组被改、返回结果、函数头 `a[]` 等价 `*a` 四件事；拆成 s5（地址传递，约 280 字）和 s6（函数头，约 100 字）后，每段都能在板上完成一个完整的状态变化。经验：单段超过 350 字或要讲两个以上“新东西”，就拆。

### 2.4 例子设计

- **选“能看见算法在干什么”的数据。** 冒泡排序首版用 `[5,3,8,1,9]`，最大数 9 本来就在最右边，看不出“冒泡”；改成 `[7,3,9,1,5]`：9 从中间一路浮到最右，共 4 轮、10 次比较、6 次交换，第一轮既有交换也有“不用换”。
- **选定例子后先手算**，再让白板动画和旁白照它走。首版脚本写过“100 个数约 10000 次比较”，正确是 n(n−1)/2，即 4950 次。
- **数字同源**：脚本、白板、字幕、简介里的数字必须来自同一个地方，改一处要全改。
- **输出必须真实运行。** 传参课用 `gcc` 编译运行四个小程序（值传递失败版、地址传递版、指针形参拷贝版、打印地址版），所有输出与地址尾号（`f504`、`f4ec`）都取自实测。
- **不编造没测的值。** 没实测 `b`、`y` 的地址，就不在板上画它们的十六进制，指针单元格写“b 的地址”。板上的地址是某一次运行的结果，旁白要说明“每次运行不一样”。

**可运行例子的写法（第 5 课补充）**

- **编译用 `-Wall -Wextra -Wpedantic -Werror`，演示“改不到”的函数也要用到参数**：`fill_value(int x){ x = 42; }` 会因 `unused-but-set-parameter` 编译失败；在函数里加一句 `printf("inside fill_value: x=%d\n", x);`，既过编译，又给出“函数里确实是 42，回到主函数仍是 0”的真实输出。
- **输入类函数用管道代替键盘**：`printf '42 tea apple hi\n' | ./demo`，输出可复现；片中必须明说“用预先给好的输入代替键盘”。
- **故意写错的例子分两种**：能编译但行为未定义的（漏 `&`）只编译、保存 gcc 警告原文、**不运行**；会写出数组外的只在板上画叉。两种都不显示运行输出。
- **旁白点名的字符与输入顺序要对上**：读入 `hi` 覆盖 `apple` 后，终点牌后面剩 l、e；预测题答案、画面格子、字幕三处同源。

### 2.5 讲解设计

1. **先直觉，后代码。** 冒泡排序先讲排队，传参课先讲故事，最后才出现代码。
2. **代码逐行对应已演示的动作。** 冒泡排序的外层循环 = 轮数，内层边界 `n-1-i` = 已就位的不用再比，`temp` 是因为交换需要暂存。
3. **口语化读符号**（配音不读括号和下标）：

   | 写法 | 旁白读法 |
   |---|---|
   | `&a` | “and 符号 a”（讲解时说“取地址符”） |
   | `*px` | “星号 px” |
   | `int a = 3` | “int a 等于 3” |
   | `%p` | “百分号 p” |
   | `n-1-i` | “n 减 1 减 i” |
   | `arr[j] > arr[j+1]` | “数组的第 j 个元素是否大于第 j 加 1 个元素” |

4. **一次只引入一个新符号**：先讲 `&`（门牌号），再讲 `*`（到这个地址去）。
5. **进阶点放在主线之后**，并明确标为“还有一个细节”。
6. **错/对成对**：常见错误页左边写错误写法配红叉、右边写正确写法配绿勾，再用一句话收束（“`px` 是门牌号，`*px` 才是住在里面的人”）。
7. **总结三句话 + 回扣故事**，最后留一句有笑意的收尾。
8. **对照与选择**：明确告诉学生“什么时候用哪一种”，并回到他们每天写的代码（`scanf` 为什么要 `&`，`printf` 为什么不用）。

**预测题（先预测，再验证）——第 3 课的做法**

- 每道题**明确重置**到同一个初始数组（7 3 9 1 5），同一道题内连续调用不重置；两道题分别考“值传递 + 地址传递叠加”和“清零 + 值传递”，答案都来自 `gcc` 实测。
- 问句之后真的安静 3 秒：配音在两个问句处**切开成三段**，拼接时插入 3 秒真实静音；`narration_timeline.json` 记录每道题的 `question_end` 和 `answer_not_before`，答案、解题动画和答案字幕都不得早于它。
- 画面上用**三点倒数**（每秒亮一个小圆点）让停顿看起来是有意的；答案出来后一句话点明“第一次是值传递，只改了副本；第二次是地址传递，改了原元素”。

### 2.6 白板画面设计

**版面规则（1920×1080）**

| 区域 | 用途 |
|---|---|
| 左上角约 (40,38) 起 | 学校/机构 logo（深蓝底板），标题避开 x<330 |
| 左半屏 | 代码（等宽字体，字号约 33，行距约 50） |
| 右半屏 | 内存图、数组、输出面板 |
| y>900 | 字幕区，板书不要进入 |
| 白板内边距 28 | 不要贴边 |

**一段一板**：每个脚本段用一块新白板，段间用 0.4 秒淡出淡入“擦板”。同一块板内内容不清空，动作累加。

**颜色语义（全片固定）**

| 颜色 | 含义 |
|---|---|
| 黑 | 常规书写 |
| 红 | 动作、强调、错误（红叉、上门手术） |
| 绿 | 完成、正确（勾、本人毫发无损、就位） |
| 黄色荧光笔 | 当前正在讲的代码行 |
| 灰 | 已消失/已释放（形参变灰） |

**节奏**

- 笔尖指针跟着书写位置走；文字逐字“写出”，线条逐笔“描出”。
- 每个内存状态之间留约 0.5 秒，让学生看清；旁白说到哪，板上就出现到哪。
- 一屏文字量上限：一块板上主体不超过“一张表 + 一个图”或“一段代码 + 一个图”。

**内存图语言（`memory` 元素）**

| 画面 | 含义 |
|---|---|
| 方框，上方名字、下方地址 | 一个变量 |
| 值从源方框飞入新方框 | 复制（过克隆门） |
| 值闪黄并变红 | 被改写（手术） |
| 方框整体变灰后淡出 | 函数返回，形参消失 |
| 红色箭头 | 地址指向（医生拿着地址找到本人） |
| 灰色小字实测输出 | 真实运行结果 |

**冒泡排序的图示语言**：数组方块；比较用红圈；交换用弧线；已就位涂绿；每一轮在下面新开一行，右侧写计数和规则。

**字体**：手写体（ZCOOL 快乐体）中文好看，但**大写 O、C 是方形字形**（“大 O”看成“大口”），代码/公式里的大写字母用等宽字体，字幕里给该字符单独指定拉丁字体；**等宽字体没有中文字形**，含中文的输出行必须用手写体。

**数字 0 也是方块**：手写体里的 `0` 和全角 `０` 都是一个小四边形，像缺字。第 3 课实测对比了 `0`、`０`、`〇`、`o`、`Ø`、`零`，当时只有 **`〇`（U+3007）** 是清晰的圆，所以第 3 课板上的零写 `〇`。**第 4 课更正**：板上同时有 a p p l e 这类字母时，`〇` 像字母 o（用户指出）。字符格里和文字里的零改用**等宽字体的数字 `0`（带点，一眼是零）**：格子里的值置空，再用 `write(font="mono")` 居中叠写；文字行里中文用手写体、零用等宽字体分两段写（第 4 课的 `zero()` 与 `mixed()`）。`〇` 只在板上没有字母、纯数字时才可接受。凡是新课里会出现 0 的地方，先渲染一帧确认。

**大写字母同样是方块**：手写体里单个大写字母（T、E、A、O、C 等）都是方形字形。格子里的大写字母（第 4 课的 `TEA`）做法：先把该格的值置空，再用等宽字体 `write` 叠写（`upper()`）；结束符 `'\0'` 同理（`endmark()`：空格子 + 等宽叠写，红色）。这些小函数在 `projects/c-strings-cn/scripts/_build_body.py`，新课直接复制。小写字母 a p l e t h i x 在手写体里正常（l 画成一根斜杠，是字体本身的样子）。

**字幕里的 c、o 也要处理**：旁白里出现 `scanf` 这类含 c 的英文词时，字幕用手写体，c、o 会显示成方块。`_build_head.py` 里把单个大写字母指定拉丁字体的正则，第 5 课扩成 `[A-Zco]`（带手写体回退，否则全角标点会变方块）。**渲染一张含该词的字幕帧并裁出字幕条目测**，不要只凭正则。板上这类词（scanf、printf、`%d`、`&`、`'\0'`）一律用等宽字体。

**手写体中文与等宽词混排一行**：先写中文，再在其右侧用 `write(font="mono")` 接写等宽词或数字（第 5 课的 `hand_mono()`，按 `est_w` 估宽度排位）；整行要消失时两段都给同一个 `until`，否则等宽那段会残留。

**一次性小标注要给 `until`**：第 4 课 s3 的“数字字符 '0'”标注忘了设 `until`，对照表出现后它还残留在板上，渲染关键帧才看到。凡是只在某一阶段出现的标注、小格、圈线，都写明消失时间。

### 2.7 音画同步

- **用字幕短语锚定白板动作**：`build_edit.py` 里 `Finder.at("短语")` 找到该短语在字幕里的时间，白板动作按这个时间出现。短语要按文本先后顺序查找；同一段里乱序使用时用独立的查找器。
- **场景计划里就写锚点**：第 3 课的计划 v1 只给每个事件一个估计秒数，对照旁白发现 b01 的动作比对应的话早 3–6 秒（旁白还没说“外面的数没变”，交换动画已经出现）。v2 给 63 个事件都补了 `anchor_phrase`（旁白里的一句话，按先后顺序），另有 24 个“后续锚点”，让相邻锚点的间隔不超过约 8 秒；剪辑阶段 `Finder.at(anchor)` 一次全部找到。**找不到锚点就停下改计划，不用估计时间硬凑。**
- **事件清单要按旁白先后顺序写**：`Finder.at()` 只往后找。第 5 课 s2 的“这就是值传递”写在“医生也一样”之前，脚本阶段断言找不到锚点，调整顺序后通过——这是该防的错，不是 bug，不要放宽查找。
- **开场和板间不留空板**：旁白一提到“上一课医生”，医生就先淡入，再画病房；`&data[0]` 卡等到旁白说出“取地址符加零号元素”才出现，不提前。
- **字幕时间是估计的**：本机没有语音识别，脚本 `make_captions.py` 按静音区间和字权重分配时间，误差约零点几秒；必须在交付时如实说明。
- **分页**：字幕在标点和自然词尾处断页，不要按 16 字硬切（会把“排序”拆开）。
- **TTS 约定**：单次 ≤600 字；不支持 SSML，停顿靠标点和段间约 0.7 秒静音；返回的 WAV 头时长字段是错的，要先用 `ffmpeg` 重封装再量时长；拼成一条总旁白轨，`loudnorm` 到约 -16 LUFS。
- **样片门**：先用最难的一段（冒泡的第一轮演示、传参的值传递演示）做配音样片，用户确认音色和语速后再批量。

### 2.8 AI 插图的用法

**分工**：数字、代码、公式、内存图全部用代码绘制；AI 插图只做“比喻性配图”（学生、气泡、克隆门、医生、床、楼房）。

**统一线稿提示词前缀（三门课通用）**

```
黑色细线手绘线稿，纯白色背景，简洁卡通风格，线条粗细一致，没有阴影，没有灰色填充，没有任何文字。
```

负面词：`阴影，灰色填充，彩色，渐变，背景，边框，文字，字母，数字，水印，照片，写实`。人物加一句“全身完整入画，双脚和鞋子完整可见，四周留出足够空白，不要切边”。

**角色一致：定妆图 + 垫图**

1. 先单独生成主角、配角的**定妆图**（正面全身像），目测通过后固定。
2. 之后每个场景把定妆图作为参考图，提示词写“图 1 中的小明”“图 2 中的医生”，并写清**人数**（“画面中只有这两个人”）。
3. 传参课的 6 张场景图都这样生成，小明的发型、T 恤和医生的帽子口罩白大褂前后一致。

**逐张目测清单**

- 人物是否全身完整（曾有学生的脚被画布截断）。
- 人数是否正确（手术台那张首版多出一个站着的小明，重做后才对）。
- 有没有出现乱码文字（医生手里的纸条上曾出现乱码字母，改成“只画三条横线表示地址，没有任何文字”后通过）。
- 动作语义是否准确（“走进门”这类动作容易变成“站在门里”）。
- 抠底后线条是否平滑：AI 输出是不透明白底，用亮度转 alpha 并裁边，放在浅色白板上。

**重试规则**：最多 3 轮，仍不满意就问用户，或改用更符号化的画法；失败图保留为 `_v1` 文件，不覆盖。

**姿态图（第 3 课）**：同一个角色需要两个姿态时（医生持纸、指向右上方），都用前课定妆图作参考、各生成一张；先审 I01 通过，再生成 I02；每张最多 3 轮，失败图保留为 `_v1`/`_v2`，仍不合格就问用户，不自动改用云端生图。抠底用前课的 `postprocess_images.py` 函数（只读导入），输出写在本课目录。

**补充：本地生图**：仓库另有 `qwen_local_image`（本地 Qwen-Image，免费、可 1–4 张参考图垫图，文生图约 45 秒、带参考图约 65–95 秒，占共享 GPU）。DashScope 仍是默认；构图难控或赶时间用 DashScope，想省钱/离线用本地。

**网上说法要用实测核对（第 6 课）**：调研时搜索摘要里有“结构体含数组成员时，按值传递也能改到数组（数组会退化成指针）”，写实验程序跑一遍，结果是 `v` 仍为 `7 3 9`，说法不成立。做法：把它记进 `research_brief` 的误区和 `decision_log`（标明来源只是搜索摘要、未打开原页）；课里用“有人说……实测不是这样”温和纠正，不点名来源；脚本只引用自己的实测；脚本元数据里写一条 `claim_check`。**例子本身就是调研**：先写会出“反直觉结果”的实验，再决定要不要把它做成这一课的看点。

### 2.9 术语与准确性

- **先定术语表，全片一致。** 传参课只讲“值传递”和“地址传递”两种，用户明确更正后，脚本、板书、字幕、简介、提案全部按此执行，并在决策记录里追加一条术语决策。
- **审批后发现文案缺词**：传参课 s7 原句缺了“指针 q”，且旁白说 `px`、板书写 `p`。做法：只改这一句，只重生成该段配音，重算时间线和字幕，交付时告诉用户。
- **准确性自查清单**
  - 所有数字：手算或实测，脚本、板书、字幕、简介同源。
  - 所有代码输出：真实运行结果，不是想当然。
  - 不暗示错误结论（例如不能让学生以为“函数里改指针形参会改外面的指针”）。
  - 隐喻边界已说明。
  - 未实测的数值不出现在板上。

**旁白无英文的取舍（第 6 课）**：结构体课里 `struct`、`card` 含 c，旁白全部改用中文（结构体、病历卡、箭头、取地址符），代码和符号只写在板上的等宽字体，于是字幕里没有 c、o 的字形风险，也不用担心 TTS 读英文。代价是旁白与板上代码的对应要靠画面：每次说“箭头”“取地址符”时，板上要同时圈出 `->`、`&`。

### 2.10 常见设计失误（反面清单）

| 失误 | 本次实例 | 修法 |
|---|---|---|
| 开场长时间空白 | 标题写完后约 10 秒没有画面，因为插图要等旁白说到“走进传送站” | 标题旁先放主角定妆图，讲到对应句子再换成场景图 |
| 一屏堆字（预防规则，三门课未发生） | — | 一块板只放“一个表”或“一段代码 + 一个图” |
| 标题被 logo 挡住 | “什么时候用哪种”的第一个字被 logo 底板盖住 | 标题起点 x≥420，其他标题避开 x<330 |
| 箭头/标签重叠 | 指针箭头穿过“swap 的房间”标签 | 标签放到框的下方；向上的箭头起点上移到名字标签之上 |
| 中文变方块 | 小单元格和输出行用了等宽字体 | 含中文一律用手写体 |
| 代码块错位 | 按 `lineAts` 乱序写代码时，未写的行被跳过，代码块上移 | 未写的行保留高度占位 |
| 演示没有真实输出（预防规则） | 冒泡首版脚本曾把“100 个数约 10000 次比较”写错（正确是 4950 次） | 数字手算、输出实测，每个演示段都配 `gcc` 真实输出 |
| 隐喻没收尾 | — | 结尾必须回扣开场故事 |
| 把工具自检当结论 | 工具的 `final_review` 曾报“有音乐/无字幕”，实际相反 | 自己用命令核对 |
| 术语与前两课冲突 | 第 3 课 v1 反复说“传值规则没有失效”，等于说 C 只有值传递，与前两课和用户更正的“只讲值传递与地址传递”矛盾 | 全课用系列术语；数组传参明确标为地址传递，复制的是地址的副本 |
| 比喻角色不统一，也没接上上一课 | 同一段里先后出现“管理员”“工作人员”“维修员”，没有用上一课的医生和“地址纸条是抄来的” | 统一为医生 + 病房 + 地址纸条；开头和结尾各回扣一次 |
| 单段讲太多 | v1 的 s5 一段 449 字讲四件事 | 拆段（见 2.3） |
| 事件只有估计秒数 | 动作比旁白早 3–6 秒 | 每个事件带旁白锚点（见 2.7） |
| 数字 0 显示成小方块 | 手写体的 0 是四边形 | 只有纯数字的板上可用 `〇`；有字母时用等宽数字 0 叠写（见 2.6） |
| `〇` 被当成字母 o | 第 4 课 a p p l e 同板，用户指出“0 画成了 o” | 零改成等宽数字 0，格子值置空叠写（见 2.6） |
| 大写字母变方块 | 格子里的 T E A 在手写体里是方形字形 | 值置空，等宽叠写（见 2.6） |
| 旁白点名的元素与画面不符 | 旁白“后面的 p、l、e 还在”，画面里 apple 下标二换成终点牌后只剩 l、e；重生成了 s9 一段配音 | 脚本阶段把旁白里每个字符、数字与画面状态逐一对照（见 2.11） |
| 一次性标注残留 | s3 的“数字字符 '0'”没设 `until`，对照表出现后仍在板上 | 每个阶段性标注都写消失时间；渲染关键帧检查（见 2.6） |
| 决策记录编号重复或重跑后重复追加 | 第 6 课脚本阶段与场景计划阶段都用了 d10；场景计划脚本被重跑又追加两次 | 各阶段的构建脚本先删本阶段旧条目再追加，并断言编号唯一（见第 6 节） |
| 字幕里 scanf 的 c 是方块 | 手写体 c、o 是方形字形；第 5 课旁白直接说 scanf | 字幕单个 c、o 指定拉丁字体，裁出字幕条确认（见 2.6） |
| 版面压线或重叠 | 第 5 课关键帧：红色地址箭头穿过“副本是抄来的”标注；`&` 圈注与说明文字挤在一起 | 样片前先出 2×2 关键帧拼图逐张看，改坐标再复拍受影响的几帧 |
| 缩略图取在动画中途或淡出时 | 第 5 课取 26.5 秒时病房只画了四间半，27.5 秒时整块白板已淡出变虚 | 取“画完且没淡出”的帧，先看图；本课最后取 27.2 秒（见 8.6） |
| 预估字数与实写差很大 | 预估 2200 字、实写 1606 字，成片 356 秒贴着目标下限；第 5 课提案 1700–1900 字、实写 1554 字，成片 327 秒（再次偏短，已告知并获批） | 写完脚本立刻按 0.22 秒/字算时长，对不上就告诉用户（见第 1 部分） |
| 缩略图取在动画画到一半 | 纸条只画了一个框和一个点 | 取帧点放到动画结束之后，先看图再导出 |

### 2.11 系列课的一致性与脚本自查清单

做系列课时，每写完一稿就对照上一课查一遍。第 3 课 v1 自审“通过”，对照本手册重审后却查出三个严重问题，所以**自审要有清单，不能凭感觉**。

| 查什么 | 怎么查 | 第 3 课的实例 |
|---|---|---|
| 术语 | 把上一课的术语表当检查表，全文搜索冲突词 | “传值规则”与“只讲值传递 / 地址传递”冲突 |
| 角色 | 同一个角色全片只用一个名字；能复用上一课的定妆图就复用 | 医生 + 病房，不再有管理员 / 工作人员 / 维修员 |
| 回扣 | 上一课的哪句话要在本课再说一次 | “地址纸条是抄来的，病房还在原处”出现在 s2 和 s5 的结尾 |
| 数字 | 引用上一课的例子时数字要一致，否则说明“用今天的数字再看一遍” | 上一课是 a=3、b=5，本课 a=7、b=3，开场加了说明 |
| 一段一个动作 | 单段超过 350 字或有两个以上新东西就拆 | s5 拆成 s5 和 s6 |
| 开场 | 第一句话说完时，板上应该已经有东西 | 医生在“上一课医生”一句出现时先淡入 |
| 映射表 | 比喻的每个角色都能在表里找到代码对应物，并写清画法只是示意 | “病房 ↔ 数组”五行对照 |
| 常见错误 | 至少一个“错写法”，只画叉、不运行、不编输出 | 数量写成 6 会越界 |
| 动作与旁白同步 | 每个画面事件有旁白锚点（见 2.7） | 63 个事件 + 24 个后续锚点 |
| 旁白点名的元素 | 旁白里列举的每个字符、数字、状态，逐一对照画面或实测输出；手推一遍每个演示的最终状态 | “后面的 p、l、e”实际只剩 l、e（第 4 课，画画面时才发现） |
| 自审的偏见 | 自己写的稿自己审容易放过；用清单重审，并把发现写进审阅记录和变更说明 | 审阅页顶部列出“相对 v1 的修改” |

**保留历史**：改稿时把上一版另存为 `*.v1.json`、`script-review.v1.html`，新版在审阅页顶部写“相对 v1 的修改”，让用户一眼看到变了什么；决策记录追加一条，不改旧的。

### 2.12 讲抽象概念：指针初步（第 7 课）

- **选题**：把前六课反复用到、却一直没细说的“地址纸条”落到变量上（`int *p = &age;`），再回答最常见的疑问：声明里的星号和使用时的 `*p` 是不是一回事。
- **一个符号两个意思**：用“出现的位置 / 意思”对照表讲，口诀是“先看它出现在哪里”——声明里是说明（格子里装的是地址），使用时是顺着地址走一趟。表里代码用等宽字体，意思用手写体。
- **改纸条 vs 改病房**：并排演示 `*q = 9;`（顺着纸条，病房变）与 `p = &n;`（只换纸条上的字，原病房不变），再顺着新纸条写 3，只有新病房变。数值沿用上一板不清屏（s3→s4→s6 是连续的一次演示：age 依次 7、8、9），两题预测题之间才显式重置。
- **旁白全中文**：p、q、age、n 只出现在板上等宽字体里，旁白说“第一张纸条”“第二张纸条”“年龄那间病房”，`*` 读“星号”，`&` 读“取地址符”；预测题也这样说。好处是字幕里没有单个字母，不会出现 c、o 的字形问题，也避免 TTS 读单字母。
- **范围**：不讲指针运算、数组与指针、`NULL`、多级指针、函数指针等；`int* b, c;` 的声明陷阱本机实测属实（`c` 只是普通整数，`sizeof` 为 4），但超出本课范围，只记在调研里。
- **错误例子如实写成警告**：漏星号（`p = 8;`）和未初始化就解引用（`int *p; *p = 5;`）在 gcc 13.3 的 `-Wall -Wextra` 下都只是警告（编译通过），加 `-Werror` 才变成错误；旁白说“实测在打开常用警告选项的情况下”，不说“一定报错或崩溃”，两种输出原文都存进 `validation/`；两个例子都只编译、不运行。
- **内存图画法**：病房＝外框 + “病房”标签 + 一个数字单元格（名字用拉丁字母）；纸条＝小格子，格子里写“age 的地址”；箭头用 memory 的 `arrows`；“改指别处”＝旧箭头加 `until`，再画新箭头，同时 `setv` 改格子里的字。
- **取帧看版面**：用锚点短语时间加书写时长之后、板结束前 0.5 秒之前的时刻；拼图里“写到一半”的帧要重取，不要据此判断版面。

## 3. 制作流程与审批门

管道：`animated-explainer`；风格：`explainer-teacher`（白板）；运行时：`remotion`；合成模式：`templated`。

| 阶段 | 做什么 | 是否是门 | 给用户看什么 |
|---|---|---|---|
| research | 联网检索现有教程、找差异点（不凭记忆写调研） | 否 | 一句话结论：现有教程缺什么 |
| proposal | 3 个概念方案、成本、渲染方案 | 是 | 概念对比、选定方案、术语与命名确认 |
| script | 逐字脚本 | 是 | 段落表、字数/估时、所有实测输出 |
| scene_plan | 每段的白板动作、图示语言、插图清单 | 是 | 场景表、版面与风险 |
| assets | 配音样片 → 定妆图 → 批量配音/插图 | 是 | 样片文件、图片、费用估价、未验证项 |
| edit | 锚定时间、逐帧看版面、30 秒样片 | 否 | 样片 |
| compose | 整片渲染 + 独立核对 | 否 | 成片与核对结果 |
| publish | 缩略图、**封面（成片开头加约 2 秒封面）**、字幕、章节、简介，本地打包 | 是 | 导出包、待确认项 |

**每个门的做法**

- 门之前只给“需要用户决定的事”，不要长篇。一个门一次批准，不合并。
- 写检查点：门控阶段先 `awaiting_human`，用户批准后再写 `completed`（`human_approved=True`）；前置阶段必须都已完成。
- 决策记录（`decision_log.json`）只追加，不改历史；类别要用 schema 允许的枚举。
- 门后发现问题：小改并重走该门（第 3 课的脚本和场景计划都是批准前经对照清单修订后再交审），改动写进审阅页的“相对上一版的修改”。
- 自审记录 `round` 在 schema 里最多到 2，重审时标 2，并在 `metadata.previous_round` 指向上一版记录。

**时间与成本参考**

- 单帧静态图渲染约 5 秒，逐段抽帧看版面比直接渲染整片省很多时间。
- 30 秒样片约 4 分钟；整片 5.5 分钟约 43 分钟、8 分钟约 60 分钟（第 3 课 467 秒用了 3624 秒）。
- 素材阶段的样片：先出一张最难的插图 / 姿态图样图和 s5 一类关键句的样音（约 15 秒），确认后再批量；整段配音实测语速后，把全课时长从估计回填为实测。
- 局部重渲染再拼接：帧范围渲染 + ffmpeg 重编码一次 + 音轨直接复制，用 md5 与逐帧 PSNR 验证。

**环境限制（本机：4 核、无 GPU、Node 18）**

- 只能用 Remotion；HyperFrames 需要 Node ≥22，Ink Theater 只跑在 HyperFrames 上，均不可用。
- Google TTS 不可用（密钥 401），用 DashScope `qwen3-tts-flash`（Cherry 女声）。
- Pixabay 音乐抓取返回 403，七门课都不加背景音乐（用户可自备曲目）。
- 没有本地语音识别，字幕时间无法用转写核对。

## 5. 质量验收清单

交付前逐项做，不要只看工具返回“成功”。

```bash
# 1. 基本信息：分辨率、编码、时长、有音频流
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,duration -show_entries format=duration,size -of compact final.mp4
# 2. 响度与峰值（目标约 -16 LUFS，峰值不削波）
ffmpeg -hide_banner -nostats -i final.mp4 -af ebur128=peak=true -vn -f null - 2>&1 | grep -E "^\s+(I|LRA|Peak):"
# 3. 黑帧、异常静音、长时间静止
ffmpeg -hide_banner -nostats -i final.mp4 -vf blackdetect=d=0.2:pic_th=0.98 -an -f null - 2>&1 | grep -c black_start
ffmpeg -hide_banner -nostats -i final.mp4 -af silencedetect=n=-50dB:d=1.5 -vn -f null - 2>&1 | grep silence_
ffmpeg -hide_banner -nostats -i final.mp4 -vf freezedetect=n=0.001:d=8 -an -f null - 2>&1 | grep freeze_
# 4. 抽帧目测（每个内存图状态、logo、字幕）
for t in 6 30 60 100; do ffmpeg -v error -y -ss $t -i final.mp4 -frames:v 1 review_frames/f$t.png; done
```

- **必看**：logo 是否每帧都在；字幕是否与旁白对应；内存图每个状态；标题有没有被遮住；有没有方块字。
- **语音段重合度**：用静音检测得到成片与源旁白的语音段，计算重合比例（前三门课分别为 96.4%、95.2%、95.0%；第 4 课未做这项比对，只核对了静音位置），作为没有语音识别时的替代证据。
- **问答停顿**：成片里超过 1.2 秒的静音应该只有问答停顿（位置对得上 `narration_timeline.json` 的 `question_end`），答案最早出现时间不早于 `answer_not_before`；再加结尾约 1.4 秒的收尾静音。
- **特殊字形**：板上有 0、大写字母、`'\0'` 的课，抽帧确认显示的是等宽数字 0 / 等宽大写 / 等宽 `'\0'`，不是方块，也不是像字母 o 的 `〇`。
- **抽帧用拼图**：第 4 课渲染前后各出 10 张关键帧，成片抽 15 帧拼成一张缩略拼图一眼看完 logo、字幕、字形；缩略图看不清的细节要在报告里写明“没有逐帧放大检查”。
- **缩略图**：先看图再导出，取帧点要在动画画完之后。
- **封面（第 7 课起每课必做，前六课已补）**：统一 16:9 版式，由 `docs/whiteboard_cover_maker.py` 生成——学校 logo（垫深蓝底，否则白字看不见）、红色“第 N 课”序号标签、手写体大标题 + 红线、一行悬念问句、等宽代码小卡片、右侧医生、右上角“C语言白板课”。新课只需在脚本 `LESSONS` 里加一行 `(项目目录, 序号, 标题, 悬念问句, 代码片段)` 再运行；英文、数字、符号一律走等宽字体（手写体会画成方块）。输出 `exports/thumbnails/cover.png`（1920×1080）和 `cover_1280x720.jpg`，并把序号写进 `exports/metadata/metadata.json` 的 `lesson_number`、`cover_path`；总览图 `projects/_covers/contact_sheet.png`，按序号命名的副本 `projects/_covers/cover_NN_<名>.png`。封面与 `thumbnail.png`（成片截帧）并存，不互相覆盖。出图后先看总览图，再放大看 logo 与标题。**嵌入视频**：`ffmpeg -i output.mp4 -i cover_1280x720.jpg -map 0:v -map 0:a -map 1 -c copy -disposition:v:1 attached_pic -movflags +faststart 新文件.mp4`，不重编码、时长与字幕时间不变；用 `-map 0:v:0 -c copy -f md5 -` 对比成片与新文件的视频流和音频流 md5，一致再替换 `exports/video/output.mp4`（`renders/final.mp4` 保持原样，二者字节不再相同）。

**片头封面规则（第 7 课起，用户要求：每课成片开头都有约 2 秒封面）**

- 做法：不重新渲染。成片渲染、核对通过后，在发布阶段运行 `.venv/bin/python docs/whiteboard_prepend_cover.py projects/<课> --seconds 2`：把封面做成 2 秒静帧 + 静音的小片段，编码参数与 Remotion 成片一致（h264 High、`yuvj420p`、30 fps、aac 48 kHz 立体声），再用 concat 拼在成片前面（`-c copy`），同时把封面图作为附加图片流嵌入（取代上一条的单独“嵌入视频”命令）。
- 脚本一并处理：`subtitles.srt` 整体后移封面时长；章节整体后移，但**第一个章节保持 0:00**（平台要求章节从 0:00 开始）；`metadata.json` 写入 `cover_seconds`，并保存 `chapters_original`，让脚本可重复运行而不叠加偏移；最后自动核对。
- 原始成片 `renders/final.mp4`、`assets/subtitles.srt` 永远不改；`exports/video/output.mp4` 是“带封面版”，与 `final.mp4` 字节不同。核对口径：封面之后第 0.5 秒的画面与 `final.mp4` 第 0.5 秒逐像素相同（实测差 0.000），时长多约 2 秒，整片能完整解码。
- 实测（第 6 课，只在临时目录里做，没有改正式文件）：390.251 → 392.272 秒（多 2.021 秒，多出的 0.02 秒是 aac 补的静音）；封面帧与 `cover.png` 平均差约 0.9（色彩空间转换所致，肉眼不可见）；脚本连跑两次结果一致；用音频互相关粗测，拼接后旁白相对画面约晚 27 毫秒，低于可察觉的程度，没有再修。
- 像素格式必须是 `yuvj420p`（Remotion 成片就是全范围）；用普通 `yuv420p` 做封面小片段会造成拼接处偏色或 concat 失败。
- 没有在播放器里目测过拼接处的衔接，只做了数值核对。
- 前六课已于 2026-10-04 统一补上 2 秒片头（每课 +2.021 秒，内容帧差 0.000）。成品集中放在 `projects/C语言白板课_成品/第NN课_课名/`，每课含 `.mp4`、`.srt`、`_封面.png`、`_简介.txt`，另有 `目录.txt` 和同名 zip；文件名避开 `&` 等 shell 敏感字符（第 5 课用“scanf与取地址符”）。新课发布时照此命名并放进同一文件夹。
- 成片的旁白时间线、场景锚点都不用改：封面是渲染之后才加的。审阅页、发布说明里引用时间点时，一律用后移后的时间。
- **必须写明做不到的**：没有语音识别转写核对；字幕时间是估计。
- **工具自检不能直接采信**：`video_compose` 的自带 `final_review` 曾错报，应自己核对后写入 `final_review.json`。

## 6. 踩坑速查表

| 现象 | 原因 | 做法 |
|---|---|---|
| “大 O”显示成“大口” | 手写体的大写 O、C 是方形字形 | 代码用等宽字体；字幕单字符指定拉丁字体（带手写体回退，否则全角逗号变方块） |
| 输出行中文变方块 | 等宽字体没有中文字形 | 含中文用手写体 |
| 白色 logo 在浅色白板上看不见 | logo 是白色线稿 | 放深蓝圆角底板，不改标识颜色；标题右移避让 |
| 代码块乱序书写时错位 | 未写的行被跳过 | 未写行保留高度 |
| 配音时长读出 44739 秒 | DashScope 的 WAV 头长度字段错误 | 先 `ffmpeg -ar 24000 -ac 1 -c:a pcm_s16le` 重封装再量 |
| 整片渲染 10 分钟就失败 | `video_compose` 默认 Remotion 超时 600 秒 | 传 `remotion_timeout_ms`（如 7200000） |
| 拼接时 ffmpeg 被 OOM 杀掉，成品缺 moov | 同一输入被多次 `trim` 会缓存已解码帧 | 每个片段独立 `-i`，峰值约 1GB |
| `pkill -f "关键字"` 把自己的 shell 杀了 | 命令行里含该关键字 | 按端口取 PID 再 kill，或停后台任务 |
| 试听服务暴露了 `.env` | 在仓库根目录起了 `http.server` | 只绑 `127.0.0.1`、指定专用目录，并 `curl` 验证 `/.env` 为 404，用完就关 |
| Pixabay 音乐 403 | 抓取被拒 | 不擅自换来源，问用户：自备曲目 / 换来源 / 不加音乐 |
| checkpoint 写不进去 | 前置阶段未完成，或门控阶段没有 `human_approved` | 补齐前置阶段；门控阶段先 `awaiting_human` 再 `completed` |
| `edit_decisions` 校验失败 | cut 的 schema 严格，不能带 `type` 等额外字段 | 两份数据：合规的 `edit_decisions.json` 与完整的 `render_props.json` |
| 校验报 `$ref` 错误 | 系统 Python 的 jsonschema 太旧 | 用项目 `.venv/bin/python` |
| Bash 安全分类器偶发无判定 | 瞬时故障 | 重试一次；仍失败先做不需要 Bash 的事 |
| 用户粘贴命令被换行截断 | 终端换行 | 命令写成一行、路径尽量短 |
| `pytest` 缺失 | 虚拟环境里没装 | 只装 `pytest`（开发依赖已列在 `requirements-dev.txt`） |
| 手写体里的 0 像缺字 | ZCOOL 的 `0`、全角 `０` 都是小四边形 | 无字母的板上可用 `〇`；有字母时用等宽数字 0 叠写（见 2.6） |
| 板上的 `〇` 被看成字母 o | 与 a p p l e 同板 | 改等宽数字 0（见 2.6） |
| 改了 `build_edit.py`，下次又恢复成旧样子 | 它是由 `_build_head.py` + `_build_body.py` 拼出来的，重新拼接会覆盖 | 改源文件，再重新拼接；只改产物等于白改 |
| 后台等待命令永远不结束 | 用 `pgrep -f "关键字"` 判断进程是否结束，会匹配到等待命令自己 | 改成检查日志文件里的结束标志，或用 TaskStop 停掉 |
| 校验脚本在系统 Python 里缺依赖 | 系统 Python 没有 PIL / pytest（第 4 课 `build_edit.py` 又栽在 `No module named 'PIL'`） | 一律用项目 `.venv/bin/python`，并设 `PYTHONPATH=.` |
| 决策记录出现重复编号 | 各阶段脚本写死编号，重跑又追加 | 追加前 `dl["decisions"] = [x for x in ... if x["stage"] != 本阶段]`，追加后 `assert len(ids) == len(set(ids))` |
| 把卡本身传给要地址的函数，gcc 是错误还是警告 | 结构体与指针类型不兼容是硬错误（`incompatible type for argument 1`）；`scanf` 漏 `&` 只是 `-Wformat` 警告 | 例子里先实测，板上如实写“报错”还是“警告”，两者都只编译、不运行 |
| `make_captions.py` 报 `FileNotFoundError: assets/captions/captions.json` | 新项目没有 `assets/captions/` 目录 | 开项目时一并 `mkdir -p assets/captions review`；配音已生成不用重配，补目录后只重跑字幕 |
| `-Werror` 下 `parameter ‘x’ set but not used` | 演示“改不到”的函数只给参数赋值 | 函数里打印该参数（见 2.4） |
| 后台渲染“完成”通知来得太早 | 通知的是启动它的外壳，不是渲染进程本身；`sleep` 等待命令还会被禁用 | 先 `ls`/日志确认进程还在，再用 `until ! kill -0 <PID>; do sleep 30; done` 加 `run_in_background` 等真实进程 |
| 等待命令超时被转后台，30 分钟后被杀 | 等待超过前台上限 | 等待命令本身也放后台，渲染进程不受影响，结束后核对日志和成片 |
| Bash 沙箱启动失败（`apply-seccomp` 权限错误） | 本机沙箱组件不可用 | 不擅自绕过，问用户；用户选“在沙箱外逐条确认”后每条命令单独申请 |
| 自己写的校验永远为真 | 把字段跟它自己比（例如脚本哈希与自己记录的哈希） | 重新计算文件的哈希再比较，并把真实比较结果写进校验记录 |
| 内存单元格的名字显示成方块 | 单元格 `name` 用的字体没有中文字形（写了“纸条”） | `name` 只用拉丁字母（p、q、age）；中文说明另写 write |
| 校验报 `credibility` 不在枚举里 | 研究报告数据点的可信度只允许 `primary_source`、`secondary_source`、`anecdotal` | 写 `secondary_source`，不要写 `secondary` |
| 术语检查把否定说明也算命中 | 提案里写了“不说引用传递”，字符串检查把它当成出现 | 提案写“不引入其他传参说法”；检查口径写“引用传递”，不要用“引用”（“解引用”是正常词） |
| 单帧看版面时画面“写到一半” | 取的帧落在文字书写动画中间 | 取帧用锚点时间 + 书写时长之后、板结束前 0.5 秒之前；缩略图同理（第 7 课取 s4 板 169.2 秒） |
| 复制模板后残留旧课内容 | 一并复制了 `_newB.py` 之类中间文件；`build_script.py` 还从上一课读审阅页做样式 | 复制后 `grep -n "c-struct" scripts/*.py` 检查，删掉用不到的中间文件，样式模板路径写进注释 |

## 7. 与用户协作方式

- **用中文、回复精简。** 嫌长就做成表或 HTML 页面；重点放在“需要你决定什么”。
- **每个门单独批准**，先出样片再批量；批准前不进入下一阶段。
- **付费调用先说清楚**：调用什么、几次、估价（写“占位估价”）。
- **不编造**：成本、耗时、来源不确定就直说；不用占位物冒充成品（曾有过静音配音 + 空白渲染还报“完成”的事故，用户拿到“没声音没内容”的视频）。
- **独立核对**：交付时列出做了哪些检查、哪些做不到、替代证据是什么。
- **用户提供的密钥**：只写入 `.env`，不在输出、日志、文档里复述；提醒作废重建。
- **看成片的办法**：用户在远程服务器上看不到浏览器，用 `scp` 下载成片，或建 SSH 隧道后访问；隧道容易断，“打不开”先建议重建或直接 `scp`。
- **审批后发现问题**：小改、只重做受影响的部分、告知用户。
- **提交代码**：先在本地保存，推送和开 PR 等用户明确要求；上游是开源仓库时，PR 只带通用改动。
- **保留商用方案**：用户要求新增本地生图只作补充时，新工具独立成文件，不改旧工具；评分里设保守值，避免免费工具在选择器里悄悄压过默认的商用方案。
- **用户中途打断**：用户拒绝某次工具调用后先停下；用户说“继续”再重试同一步，不换路线。
