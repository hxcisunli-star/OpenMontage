# v4 CPU 实测（2026-10-07 至 10-08 CST）

所有列入表格的任务都通过在线 agent 提交，运行于正式 systemd cgroup。内存和线程为每 3 秒采样的峰值；耗时为首个 job started_at 到最后一个 finished_at，不包含上传、下载、音轨合并。没有 GPU/NVENC 实验。

## 300 帧 K4 视频与六张静帧

参考区间为 3173–3472（含首尾）。短任务耗时包含六张静帧。视频 PSNR 为逐帧平均值/最低值；SSIM 为 FFmpeg 汇总。每行六张静帧均 PSNR=inf、SSIM=1。

|配置|秒|fps|峰值MiB|峰值线程|PSNR均/最低 dB|SSIM|结论|
|---|---:|---:|---:|---:|---|---:|---|
|cpu-w16-isolated|14.493|20.7|7619|2541|50.14/48.31|0.997341|PASS|
|cpu-w24-repeat|14.349|20.91|10487|3743|49.52/43.88|0.997045|FAIL|
|cpu-w24-balanced|14.454|20.75|10308|3776|49.49/47.83|0.997022|PASS|
|cpu-w32|15.927|18.84|12942|4911|49.03/47.44|0.996675|PASS|
|cpu-w48|19.602|15.3|17408|7136|48.28/46.69|0.996148|PASS|

cpu-w24-repeat 使用原 ceil 分块，末段只有 1 帧，最低值出现在第300帧。保留失败记录。cpu-w24-balanced 改为24段均分（12/13帧），其他画面/编码参数不变，恢复达标。此改法只用于本机自测；144 的源码未修改。初次 cpu-w16 曾混跑其他课程，不列入性能排名；表中使用隔离复测。48 worker 已验证但比16/32慢，因此未发布48-worker预算。

## 同一完整课程：11300帧 / 1920×1080 / 30fps

整课行的 PSNR/SSIM **仅比较参考包可用的 K4 300帧区间**，不是整片逐帧对参考机验证。输出总帧数另用 ffprobe 核验。

|配置|CPU核配额|job×worker|秒|fps|峰值MiB|峰值线程|K4均/最低 dB|SSIM|
|---|---:|---|---:|---:|---:|---:|---|---:|
|full-1x16|48|1×16|203.723|55.47|27373|4071|51.92/50.40|0.998140|
|full-2x16|48|2×16|206.349|54.76|52290|7936|52.08/50.34|0.998159|
|full-4x8|48|4×8|205.940|54.87|53167|8202|52.15/50.28|0.998199|
|baseline-2x8-quota16|16|2×8|498.581|22.66|27096|3595|51.92/50.40|0.998140|
|final-4x8|48|4×8|210.545|53.67|53056|8189|52.15/50.28|0.998199|

同课旧配额对照 498.581s → 发布配置复验 210.545s，提速 2.37 倍、耗时降低 57.8%。旧配额对照采用修复后的线程上限和缓存，仅还原CPU16核/2×8 worker，以免混入进程耗尽故障。

首轮三种组合203.7–206.3秒，单次差距约1.3%，不足以认定严格性能排序。单job×16实测数值最低；发布4×8允许多个课程分组同时推进，吞吐近似，且满足4job共32worker稳定性检查。最终没有把48 worker宣传为更快。

原始证据保存在渲染机 `/srv/openmontage-render/bench-v4/evidence/<配置>/`：`poll.jsonl`、worker日志、manifest、逐帧PSNR、静帧、分片和joined.mp4。所有 manifest 中的大小和 SHA 已逐项核验。
