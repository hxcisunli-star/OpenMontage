# 用时分析：试验视频《让AI自己拿主意，值吗？》（agent-workflow-or-agent-cn；试验品，不属于课程）
起因：用户问“C 语言白板课平均 40 多分钟一课，这支做了 10 多个小时，效率差在哪”。本页的数字来自 `docs/whiteboard_timeline.py`（读 approvals.jsonl）、文件时间戳和 Codex 事件日志；推断的地方写了“推断”。时区：文件时间为本机（UTC−7），口令记录为 UTC。

## 一、实测的时间（截至剪辑阶段进行中）
| 来源 | 数字 |
|---|---|
| 项目建立之前的策划、演示程序、真实实测、母稿 | 约 4 小时（推断：工作区文件时间 10-27 05:54–09:50 本机） |
| 提交计划到项目建立之间的空档 | 约 11.3 小时（10-27 09:50–21:09 本机）。用户“计划确认”发生在这段里，具体几点没有记录（推断：基本是等用户，不是生产） |
| 五道口令内的生产时间（计时工具） | 提案 0.28 + 脚本（含教案页）1.95 + 场景计划 1.04 + 样音 0.30 + 素材 1.13 = **4.70 小时** |
| 五道口令内的“等用户”（计时工具） | 提案 0.08 + 脚本 0.83 + 场景计划 0.11 + 素材 0.11 = **1.13 小时** |
| 剪辑阶段 | 10-28 09:59 UTC 起，进行中（还没到样片、合成、发布） |
| 对照：agent-messages-cn（上一支试验，口令全走完到发布） | 生产 2.51 小时、等用户 3.20 小时。**口令间隔 5.4 小时里一半以上是等用户，不是生产** |

结论：用户感觉的“10 多个小时”由约 4 小时的项目前策划＋4.7 小时的口令内生产＋1 小时多的剪辑＋等用户的一部分构成；到现在为止的生产时间约 10 小时，与感觉吻合，而且还有三个阶段没做。

## 二、差在哪（按影响从大到小）
1. **不是同一种活**：新系列首课加原创实验。C 课的代码例子 gcc 秒出结果；本课要真调模型，演示程序返工 8 轮、复查 4 轮，盲写另一批顾客，跑五遍实测。光项目前这一段约 4 小时，C 课没有。
2. **零件现造**：新系列没有现成的构建脚本、板书助手、生图脚本，本课全部现写（E74）；这些只付一次，第二课复用。
3. **审稿层数多**：脚本阶段事实核对、红队、读者测试各做了两三轮；第二、三轮大多重复第一轮已改完的意见。
4. **档位错配**：设计和板书代码用 astra＋max，一路 33–55 分钟；返工用 sol 平均 8 分钟。astra 的板书一路跑到 55 分钟超时上限（s1 被截断，没发最终消息，代码已写完能过构建）。
5. **串行三段加同步等待**：起草、审稿、返工，每段等最慢的一路。
6. **可避免的失误**：
   - 等一个不存在的 final.txt，白等约 48 分钟（脚本阶段）。
   - 生图批处理顺序写成串行，慢约 10–15 分钟。
   - 中途换模型通道（百炼→七牛云），之前的数据作废重跑。
   - `pkill -f` 杀了自己的 shell。
   - Codex `-i` 图片参数吞掉提示词（第一次）。
   - **素材阶段审姿势漏看胳膊：**老师指板姿势（`teacher_point_right_hand`）生成时就是跨身体指向另一边，我水平翻转后，举起的和垂着的胳膊挤在同一侧肩膀上；用户看第三关（K6）画面时发现。审姿势时只看了“手指向哪边、几根手指”，没数“每条胳膊接在哪个肩”，也没在翻转之后再看一遍。重画一次（两个版本各 3 张，约 1 分钟生成）并重做全部关键帧、样片、排版检查，多花约 40 分钟。以后审姿势：翻转前后各看一遍，逐条胳膊追到肩膀；放进板里的实渲帧里老师要看全尺寸。
   - **剪辑阶段：8 路并发里 2 路（s3、s6）启动一分钟就被中转站拒（“Concurrency limit exceeded”），我只检查了文件有没有出现，没看事件日志，把它们当成“还在写”等了约 55 分钟。**
7. **质量门槛是用户主动抬高的**：35 张生成图、18 个新姿势、118 个事件的板书、教案页。
8. **等人**：九道口令，审阅页约 6 张。

## 三、改动（已记入规则）
- 新增 `docs/whiteboard_timeline.py <项目> [--since …]`：每道口令的“生产／等用户”小时数。已知限制：项目建立之前的工作不在记录里，要用 `--since` 手填；`样音通过` 用 `record` 写的，没有 awaiting_since，全算生产。
- 两条道：标准道（模板＋确定性例子）和试验道（真调模型、新系列、新图），开题时由用户定。
- 审稿轮次上限：事实核对 1 轮、红队 1 轮、读者测试 1 轮；之后只复核改过的句子。
- 档位：astra＋max 只做美术设计和互相矛盾的裁定；板书代码和返工默认 sol；机械活 terra。
- 等待：只按进程结束等；**启动后 60 秒内检查每路事件日志，有 `turn.failed` 或 `error` 立刻补发**；工作区先建 `out/`；批处理默认并行。
- 并发：8 路大模型（astra）一起发有 2 路被拒；一波别超过约 6 路大模型，失败的补发。
