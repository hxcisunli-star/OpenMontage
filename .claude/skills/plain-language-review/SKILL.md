# 通俗度人工核对（费曼式）

`build_script.py` 现在只能**统计**通俗度：平均句长、最长句、英文与数字个数、难词表命中。它查不出两件事：
1. 新词那句“大白话”是不是真的不靠别的术语；
2. 比喻（纸条、病历卡、医生、排队……）说过头没有——**哪里像、哪里不像**。

上游方法来自 OpenMAIC 的费曼学习法（原文见 `references/upstream-feynman-learning.md`；它的 `interactive` 页、小白代理等是它自己运行时的东西，本项目没有）。本项目是旁白视频，没有学习者实时输入，所以只取**检验办法**，用在写脚本的人身上。

## 不要这样用
- 不把“费曼”“最小缺口”“类比破坏测试”这些词写进旁白、板书、简介或字幕；它们只用在核对和报告里。
- 不声称视频能“实时诊断”学生；视频里能做的只有“先猜后看”的中途预测。

## 检查清单（脚本通过前逐项做，结果写进 `projects/<课程>/validation/plain-language-review.md`）

### 1. 去术语测试
对本课点名的每个**新词**（例如“撞名”“前提”“来回测试”）：
- 用**不含本课任何术语**的一句话讲出来，写在表里；
- 旁白里那句大白话必须就是这样，不能靠另一个没讲过的词（“撞名 = 命名冲突”不及格）；
- 讲不出来，说明这个词该删或该拆。

### 2. 类比破坏测试
对本课每个比喻列一行：
| 比喻 | 哪里像（旁白用到的） | 哪里不像（旁白没说，也不能暗示） | 旁白有没有越界 |
|---|---|---|---|
- 有没有一句旁白把比喻当成事实用？（例如把“纸条”说成“就是地址”）
- 至少找出一个失效点；若这个失效点正好是本课要纠正的误解，就写进难点表。

### 3. 每个难点只补一个最小缺口
难点表每一行写成“学生怎么想 → **差的那一步**”，不要把整本教材塞进一行。一行里出现两个缺口就拆成两行或删一个。

### 4. 先讲后看还是先猜后看
确认**中途预测在讲解之前**（先猜，再给答案），答案在真实静默之后才出现；这是本项目已有做法，核对即可。

### 5. 能不能讲回去
为课后练习准备一题“用自己的话，讲给一个没学过的同学听”（把句子交给 `exercise-design`）。

### 6. 板书与旁白的“红线”
学生可见的文字（板书、字幕、标题）只写动作语言（“先猜一猜”“再对一对”），不写规划标签；旁白里不出现英文字母与阿拉伯数字（沿用既有约束）。

## 报告写法（短）
一张表放“新词 / 去术语一句话 / 是否及格”，一张表放比喻，再写 3 行结论：有几处改了脚本、几处需要你拍板、有没有删词。把结论摘要写进请用户审阅脚本的回复。

## 完成标准
- 每个新词都有“去术语一句话”并且已出现在旁白里；
- 每个比喻都有“不像”的一行，旁白未越界；
- 难点表每行一个缺口；
- 报告已保存，脚本若有改动已重跑 `build_script.py` 并确认统计仍过关。
