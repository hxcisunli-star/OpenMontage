# 逆向设计一页纸（UbD）

现在的策划流程先写“选题核对、研究结论、课程草案、难点表”，**没有先回答“学生靠什么证明学会了”**。逆向设计把顺序倒过来：**先定预期结果，再定评估证据，最后才设计讲解**。上游方法来自 OpenMAIC 的“理解本位设计”（原文见 `references/upstream-understanding-by-design.md`；它的页面类型 `slide`/`interactive`/`pbl`、课堂创建流程是它自己运行时的东西，本项目没有）。

## 放在计划文件的什么位置
计划文件（`/root/.claude/plans/…`）里，在“选题核对”之后、“课程草案”之前，加一节“**教学设计一页纸**”。这一节只在计划与提案里出现；**这些词不进旁白、板书、字幕、简介**。

## 一页纸的四块
### 1. 持久理解（1–3 句）
学生离开后仍然带得走、能迁移的**想法**，不是事实清单。
- 好：“两个各自正确的零件拼在一起，错常出在零件之间”；
- 差：“编译器会报 redefinition”。

### 2. 基本问题（1–2 个）
开放、可以回到的问题，也是第 1 段的“进来的疑问”。例：“叫号机和病历册各自都能用，直接放在一起行不行？”

### 3. 评估证据（先写，后设计）
| 证据来源 | 它证明什么 | 对应哪一段 |
|---|---|---|
| 中途预测题（s2） | 能不能在看答案前做出判断 | s2 |
| 结尾两道预测题（s8） | 能不能把理解用到新情境 | s8 |
| 两份考卷（s2、s6） | 能不能用考卷说明“对”是什么 | s2、s6 |
| 三个常见错误（s7） | 能不能分辨错在哪一层 | s7 |
| 课后练习（含新题独立复核） | 离开视频后能不能自己做出来（见 `exercise-design`） | 发布包 |

先写这张表，再回头看课程草案的每一段是不是在为它们**提供概念、证据或练习**。

### 4. WHERETO 对照（检查表，不是模板）
| 字母 | 含义 | 在 8 段里的位置 |
|---|---|---|
| W 去哪、为什么 | 学生知道要去哪、为什么值得 | s1 进来的疑问 |
| H 钩子 | 有冲突的真实情境引出基本问题 | s1 |
| E 装备 | 用证据与逻辑链建立概念 | s3–s5 |
| E 亲身经历 | 看真实输出、先猜后看 | s2、s4–s6 的演示与预测 |
| R 反思、修正 | 换情境重做、错了怎么改 | s7 错误、s8 预测 |
| T 量体裁衣 | 不同起点的学生 | 课后练习的两条路线 |
| O 组织 | 理解逐步生成，最后回到基本问题 | s8 三句回顾 |

缺哪一格，就在草案里补一格；某一格多了就合并。

## 质量关口
- 每一段都能回答“它在服务哪个持久理解或基本问题”；**答不出的段或句，删或改写**（脚本偏长要删句时，用它决定删哪句）。
- 新东西仍然只有一两个（沿用既有的四条选题标准）。
- 表现性证据落在课后练习的“自己写”与“新题独立复核”，不是课末突然加一个没铺垫的任务。
- 系列课先确认整个单元的蓝图，再逐课策划（本项目已有逐课审批，保持）。

## 边界
不用于视觉风格、讲师口吻模仿、PPT 导入；不改变既有的审批门与流程纪律。
